## 哪种情况技术上跑通也算失败
- 修完后真留桩漏拦：`TODO`、`FIXME`、`XXX` 作为独立词、`NotImplementedError`、`fatalError(`、`unimplemented!`、`todo!(`、`not implemented` 任何一种在代码文件新增行里不再命中。
- 否定句规则把「不改接口，重做记忆服务」这种后半句的重做也放过。
- tests 规则让别的模块认领的测试文件、或非测试的未收录文件越界放行。
- `--check` 带 `--plan-dir` 时把本场次自己没合并的任务或没验收的任务漏掉。

## 两三种做法和选的那种
留桩：A 删掉 `XXX`；B 仅匹配注释；C 大小写敏感加词边界，小写 todo 只在注释起始符后算。选 C，因为 A 放掉真的 XXX 待补，B 放掉独立一行的 `TODO`，而现有用例 C3-vocabulary 要求这样的行被拦。
tests：A 把 tests 目录加进固定放行名单；B 测试文件没有任何模块认领时放行。选 B，A 会放行别的模块认领的测试。
`--check`：A 带 `--plan-dir` 时只查本场次；B 只丢「任务书指向别的场次」的条目，其余照旧。选 B，旧用例 C6 要求没有场次归属的已合并未清副本也计入，A 会改掉这条行为。
