# Roadstar · 引路星

今天跟大家分享一个我自己做的 Claude Code 技能，叫 Roadstar，中文名引路星。我从 9 月 24 号开始做，用到现在差不多三个星期了，光是 10 月 4 号以后就在四个项目里跑了十七场，派出去的 Codex 会话有两百四十多次。我个人来讲用下来是非常满意的，因为它解决了我三个非常大的问题。

## 它解决了我三个问题

首先第一个是两边订阅浪费的问题。我手里 Claude 和 GPT 两边都有订阅，但是以前基本只用 Claude，所以 Claude 的周额度经常用到一半就撞上限，GPT 那边钱照样交，额度却大部分闲着。现在 Claude 只当总调度，想方案、拆活、派活、验收，真正写代码的活交给 Codex，那两百四十多次里有一半以上是便宜的 6.1 Sol 干的，所以两边的订阅都用上了，而且 Claude 的额度全留给了它最擅长的指挥和整理。

再有一个是方案一次想不完的问题。同一件事让 AI 想完了，再说一句「再想想」，它总能再想出几个新的点来，而且 Claude 看不出来的问题 Codex 一看就能看出来，反过来也一样。所以 Roadstar 让两家最强的模型围着同一份方案互相挑错，每条意见都要带证据，比如哪个文件哪一行，默认谈三轮，两边都没新问题了就提前停，所以方案交到我手里的时候，大部分坑已经被另一个模型提前踩过了。

另外一个是派活和验收太累的问题。以前一个大项目我得自己想哪块给谁，做完了还得自己一条条去验，非常的累。现在 Claude 会把项目拆成一件件两个小时之内能做完、能单独验收的小活，每件写清楚给哪个型号、做完长什么样、时间上限多少、谁来审，我只在几个关键的地方拍板，而且每一步都记在文件里，回头都能翻。

## 怎么用

在项目里对 Claude 说一句「用 skill」就可以了，它自己看现场判断走哪一种，开场报一行配置就开始跑，不等我答复，我想改哪项接着说一句就行。

- 探讨：我只有一个想法的时候，Claude 写方案、Codex 来审，谈到能落地给我一份大白话纪要和拆分表，我说开工它才动手。
- 复盘：项目已经有了，两边各读一遍，按能不能上架收费、或者按模块一块一块找 bug，交叉审出不足清单和先做的三件事。
- 协同：方案已经有了，直接拆活、派活、验收，最后交完工报告。

一个小时之内能干完的小活它不走这套流程，直接做掉。

## 我最满意的几个地方

- 额度它自己看。开场那一行会报两边额度是宽、正常、紧还是空，是一个探针一秒多读出来的，不花额度；哪边宽活就往哪边派，读到紧了它一定停下来问我。模型最后拍板的永远是我，我说一句「这个月多用 GPT」，它这段时间都照着排。
- 干活的和验收的一定不是同一个型号。Astra 写的让 Sol 复核，Sol 写的让 Astra 复核，或者 Claude 自己把验收命令重跑一遍；全部过了以后，Claude 还要在合并后的主干上亲自再跑一遍完整测试，Codex 自己报的数字只当参考。
- 每条线都带止损。之前有一条做性能的线跑了七个半小时，烧掉我三成周额度，所以现在派出去就带时间上限，到点脚本直接停；同一个问题两轮没收敛，就换 Claude 这边的主模型亲自查根因。
- 踩过的坑当天写成规矩。现在里面有三十来条，比如完成线必须能失败、「顺滑好看」这种词不许直接进任务书、同时跑的模拟器最多两台，每一条后面都写着是哪个项目哪一次摔出来的。
- 有界面的活，设计方向出两三版我来挑，选定以后默认打磨两遍、过两遍 review 才给我看。

## 不是特别方便的地方

它是按两边订阅都有来设计的，审方案和派活的两份脚本要本机装着 Codex 命令行，版本 0.160 以上。只订阅 Claude 的朋友也能跑单家模式，审方案换成 Claude 另开一个实例来挑错，执行走 Haiku、Sonnet、Opus 这条梯子，但是少了两家互相挑错那一层，而且这个模式还没在一整场里实跑过；只订阅 GPT 的版本我还没做。另外跑一场探讨要用掉两边的额度和半小时到一小时的时间，但是因为大活返工一次的代价远比这个高，所以对我个人来讲影响不大。

## 装

```bash
git clone https://github.com/Rurutia-Artemis/Roadstar.git
cd Roadstar && ./install.sh
```

然后重开一个 Claude Code 会话，说一句「用 skill」就可以了。

总之我个人来讲，两边订阅都有、经常让 AI 干一个小时干不完的大活的朋友，这个东西非常值得试一下；平时只改改小东西的朋友，其实不用特别的着急。试的时候哪里不顺手，直接告诉我就行。OK 那，这些就是我这段时间做 Roadstar 的一些体会，希望对大家有一定的参考价值。
