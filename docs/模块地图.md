# Roadstar 模块地图

更新：2026-10-05　对应提交：`83e5147`

## 一句话

Roadstar · 引路星是本机 Claude Code 与 Codex CLI 共用的协作 skill：Claude 主会话主持探讨、复盘或协同，Codex 审稿或执行任务，文件账本保存决定与验收证据；没有独立应用、开发服务器或构建流程。

## 怎么跑、怎么测

以下命令从 `/Users/rurutia/Documents/RuruCode/Roadstar` 执行。本页命令均已核对脚本来源，本次未运行。

- 安装：`./install.sh`，把 skill 和 Claude 子代理软链到两家的发现目录；完成后重开 Claude Code 会话。
- 使用：在 Claude Code 中输入 `/roadstar`，或说「开圆桌」「复盘这个项目」「直接调度」。
- 前置条件：README 要求 Codex CLI ≥ 0.160、ChatGPT 账号登录及 Claude Code Max；Python 脚本只用标准库，Shell 脚本使用 Bash。
- 额度读数：`python3 skill/scripts/quota-status.py`；机器读取加 `--json`。不发送模型推理请求，但会启动 CLI 子进程、使用临时目录并查询账号额度。
- 全量回归：`bash skill/scripts/tests/run.sh`。自动把两家 CLI 替换成本地桩，不联网、不调用真实模型；会创建临时文件与子进程，结尾输出 `PASS <数量> checks`。耗时未测。
- 局部检查：见各模块。测试脚本没有模块筛选参数，局部检查不能替代全量回归。
- 改动后的项目规定：更新 `CHANGELOG.md`，运行桩测试及 `./install.sh`；具体提交权限服从当前任务授权。

源码入口是 `skill/` 和 `agents/`；`docs/` 保存本仓库升级材料。实际协作场次通常落在**被协作项目**的 `docs/roadstar/<日期>-<slug>/`，不要把本仓库升级记录当成所有项目的运行日志。

## 出了问题先看哪

下文 `<场次目录>`、`<任务号>`、`N` 是占位符，例如任务号 `T3`；`rounds/` 下的日志与状态文件按运行生成，不保证每场都有。

|---|---|---|

| 「额度档位忽然变了／一直不变」 | 额度探针 | `window_tier()`、`hysteresis()`；核对是否传了 `--prev` 及完整上次 JSON |

## 流程与调度契约

- 管什么：定义探讨／复盘／协同的流程、选模型与推荐分工、议题处置、停机和定稿条件。
- 入口：`skill/SKILL.md`、`skill/references/modes.md`、`skill/references/division-of-labor.md`、`skill/references/ledger-format.md`。
- 对外接口：skill 的 `name`／`description` 触发契约；场次文件 `brief.md`、`plan.md`、`ledger.md`、`rounds/`。
- 依赖：额度探针、审稿及执行模块；被谁用：Claude 主会话、两家执行者与验收者。
- 怎么测：无独立文档契约测试；人工对照模板、流程与脚本，配套回归用 `bash skill/scripts/tests/run.sh`。
- 规矩：按已授权的模型与分工执行；议题有证据、决定进账本；任务书写模块名；入口、接口、测试或规矩变更同步更新地图。
- 细节：`skill/references/plan-template.md`、`minutes-template.md`、`task-brief-template.md`、`project-map.md`、`models.md`、`pro-stage.md`（均相对 `skill/references/`）。

## 额度探针

- 管什么：并行查询 Claude／Codex 额度，归一化窗口、套餐、重置卡与 credits，计算「宽／正常／紧／空」及两次确认换档。
- 入口：`skill/scripts/quota-status.py`、`skill/scripts/tests/bin/codex`、`skill/scripts/tests/bin/claude`。
- 对外接口：`python3 skill/scripts/quota-status.py [--json] [--prev <上次JSON>]`；JSON 含 `claude`、`codex`、`note`，两家均不可用时退出码为 2。
- 依赖：Claude 控制协议 `get_usage`、Codex app-server `account/rateLimits/read`；被谁用：开场、调度及 `dex-exec.sh`。
- 怎么测：`PATH="$PWD/skill/scripts/tests/bin:$PATH" python3 skill/scripts/quota-status.py --json` 使用本地协议桩做读数冒烟；边界、滞回与失败清理在全量桩测试中。
- 规矩：不发送推理请求、不输出账号身份；Codex 实时读取失败才降级到本地 rollout，Claude 不用该降级源；无数据不能当额度充足。
- 细节：`skill/references/division-of-labor.md` §2–4；状态由调用方保存完整 JSON，探针不持久化读数，但会使用临时目录。

## Codex 审稿

- 管什么：生成逐轮请求、方案快照与 diff，调用只读 Codex 输出结构化审稿，再渲染成人可读文本。
- 入口：`skill/scripts/dex-review.sh`、`skill/scripts/render-review.py`、`skill/references/dex-review-prompt.md`、`skill/references/dex-review.schema.json`。
- 对外接口：`bash skill/scripts/dex-review.sh <场次目录> [--model M] [--effort E] [--root DIR] [--full] [--dry-run]`；输入须有 brief／plan／ledger，产物为 `rounds/rN-*`。
- 依赖：Codex CLI、Bash、Python、diff 与审稿 schema；被谁用：流程内环及主会话账本整理。
- 怎么测：`bash skill/scripts/dex-review.sh docs/2026-10-04-dispatch-upgrade --root "$PWD" --dry-run` 检查请求拼装、不调用模型；仍会创建 rounds 目录及临时文件，不适用于只读沙箱。
- 规矩：默认 `gpt-6-astra/high`、只读沙箱、关闭 fast_mode；PASS 的逐项清单与零阻塞要求属于审稿契约，脚本不会完整替主持人判定定稿。
- 细节：`skill/SKILL.md` §3–7；渲染命令 `python3 skill/scripts/render-review.py <审稿JSON> [--round N] [--from Dex]`；脚本默认只发送第二轮起的 diff 与筛选账本。

## 任务执行与验收

- 管什么：派发单份任务书、保存请求与结果、后台状态及续接；Claude builders 实现，checker 独立核验。
- 入口：`skill/scripts/dex-exec.sh`、`agents/roadstar-builder.md`、`agents/roadstar-checker.md`、`skill/references/task-brief-template.md`。
- 对外接口：`bash skill/scripts/dex-exec.sh <场次目录> <任务号> --model M --effort E --brief FILE`；支持 `--write`、`--resume`、`--detach`、`--status`、`--force`、`--dry-run`。
- 依赖：Codex CLI、额度探针及 Claude Agent 工具；被谁用：流程调度；产物为 `exec-T*.md`、请求副本、`.meta`、`.pid`、`.exit` 与日志。
- 怎么测：`bash skill/scripts/dex-exec.sh docs/2026-10-04-dispatch-upgrade T99 --model gpt-6-astra --effort high --brief docs/2026-10-04-dispatch-upgrade/brief.md --root "$PWD" --dry-run`，只打印命令与路径，不查额度、不执行任务、不写产物。
- 规矩：模型／强度／任务书必填，默认只读；额度「空」退出 3，探针失败则警告后继续；重复派发保留请求快照，结果和元数据更新；旧锁不自动清理；执行者不提交。
- 细节：`skill/references/division-of-labor.md` §8–11；`agents/roadstar-builder-hard.md` 为 Opus/xhigh，`agents/roadstar-builder-light.md` 为 Sonnet/medium；checker 的报告写回要求与禁止写工具配置需一并核对。
