# Roadstar 模块地图

更新：2026-10-16　适用版本：1.13.0（上一版 1.12.0，`a037ff4`）

## 一句话

Roadstar · 引路星是本机 Claude Code 与 Codex CLI 共用的协作 skill：主席说「用 skill」，Claude 主会话按「先判用法」路由走续接 / 直接干 / 探讨 / 复盘 / 协同，Codex 审稿或执行任务，每条派出去的线带时间上限止损，文件账本保存决定与验收证据；没有独立应用、开发服务器或构建流程。

## 怎么跑、怎么测

以下命令从 `/Users/rurutia/Documents/RuruCode/Roadstar` 执行。本页命令均已核对脚本来源；本轮实跑范围见末节。

- 安装：`./install.sh`，只把 skill 软链到两家的发现目录，不管理 Claude 子代理目录；完成后重开 Claude Code 会话。
- 使用：在 Claude Code 中说「用 skill」「用 Roadstar」或 `/roadstar`，主会话按 `skill/SKILL.md`「先判用法」表自己判走哪种，开场一行报出来就跑；也可点名「开圆桌」「复盘这个项目」「全面 review」「直接调度」。
- 前置条件：codex-cli ≥ 0.160（本机 10-10 核对 0.160.0）、ChatGPT 账号登录、Claude Code Max；Python 脚本只用标准库，Shell 脚本使用 Bash。
- 额度读数：`python3 skill/scripts/quota-status.py`；机器读取加 `--json`。不发送模型推理请求，但会启动 CLI 子进程、使用临时目录并查询账号额度。
- 全量回归：`bash skill/scripts/tests/run.sh`。自动把三家 CLI（claude、codex、grok）和 gh 替换成本地桩，不联网、不调用真实模型；会创建临时文件、子进程和临时 git 仓库，结尾输出 `PASS <数量> checks`（10-16 本版实跑 PASS 94）。
- 开场三件套：`python3 skill/scripts/quota-status.py --json > probe.json && python3 skill/scripts/quota-estimate.py --probe probe.json --session 探讨 > panel.json && python3 skill/scripts/panel.py --estimate panel.json --usage 探讨 --title 题目 --host-model "<主会话实际型号>"`；排期：`python3 skill/scripts/schedule.py --plan <plan.md> --probe probe.json --start HH:MM`。
- 局部检查：见各模块。测试脚本没有模块筛选参数，局部检查不能替代全量回归。
- 改动后的项目规定：更新 `CHANGELOG.md`，运行桩测试及 `./install.sh`；改了模块入口、接口、测试命令或规矩，同一提交更新本页那一节；踩了新坑当天进 `division-of-labor.md` 第 15 节或项目 `_common.md`。

源码入口是 `skill/`；`docs/` 保存本仓库升级材料。实际协作场次落在**被协作项目**的 `docs/roadstar/<日期>-<slug>/`，不要把本仓库升级记录当成所有项目的运行日志。

## 流程与调度契约

- 管什么：先判用法路由，探讨／复盘／协同的流程，开场一行与模型默认值，拆活与分配，议题处置，停机、定稿与止损条件。
- 入口：`skill/SKILL.md`（「使用步骤」一节是每屏配方）、`skill/references/screens.md`（每屏例子与命令）、`modes.md`（含续接）、`division-of-labor.md`、`strategies.md`（四种策略）、`estimates.md`（预估默认值与校准）、`ledger-format.md`、`models.md`、`providers.json`（型号登记表）。

- 依赖：额度探针、审稿及执行模块；vela 的 `references/ui-acceptance.md`；被谁用：Claude 主会话、Codex 执行者与验收者。
- 怎么测：`bash skill/scripts/tests/run.sh` 里有两条文档契约测试：`strategies.json` 自动列和 SKILL §8 表逐行相同；`providers.json` 过 `providers-check.py`。其余人工对照模板、流程与脚本。
- 规矩：开场一条消息里先贴面板（数字只来自脚本）、问一次策略（回车 = 自动，只管本场，记账本）、贴分配预览，探讨再加开场说明；按路由表取第一条命中；策略只改起步层，自动分配就是 §8 表，表只随新版本更新（Claude 按门槛自动改表发版，主席每周一句「可以迭代了」）；质量优先下额度不够停下来问；调研类活交 Grace；本版不接 API；试新型号开且已登录时仅试派 Grok 取证、复核只读活，战绩满 5 条再决定进不进起步表；探讨开头先做功能地图（新产品或带界面的新模块，两家按十个角度把副功能、设置、衍生功能想全，主席分档后才谈工程，`references/feature-map.md`），纯工程改动跳过；拆活和分配只由 Argo 做，Dex 只讨论、执行、复核；实现默认交 Codex；Claude 四层按活常驻（Haiku 5.5 取证与批量、Sonnet 跨家复核不看 Codex 额度，Sonnet／Opus 做实现按额度方向，Fable 只在两轮没收敛或审方案要最强时派），Claude 紧时常驻活退回 Codex、实现梯子关闭；本机没有 Codex 进单家模式（审稿 Fable 子代理、执行 Claude 梯子、脚本不跑、纪要写明同家）；每条线带时间上限并写进度文件，碰壁就停、只把没过的检查项交高一级补全，派活战绩进 `.meta`，经验表样本够了按门槛提起步层调整交主席拍板；有界面的活按 vela 界面验收标准亲验；设计类的活先从 Huemo 配套动效、图标、配色写进任务书，方向稿出 2–3 版由主席挑，完成线含两遍 review 与默认两遍打磨记录；议题有证据、决定进账本；任务书写模块名并引用 `_common.md`；入口、接口、测试或规矩变更同步更新地图。

- 细节：`skill/references/screens.md`、`strategies.md`、`estimates.md`。

## Codex 审稿

- 管什么：生成逐轮请求、方案快照与 diff，调用只读 Codex 输出结构化审稿，再渲染成人可读文本。

## 碰壁止损与派活经验

- 管什么：执行方每试一次检查项写一行进度，`stall-watch.py` 判断该不该停；停下后做完的收下、没过的交升级链高一级补全；每次派活的类别、型号、结果、额度差进 `.meta`，`dispatch-stats.py` 汇总成经验表，给起步层调整建议。
