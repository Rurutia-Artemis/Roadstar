# Roadstar 模块地图

更新：2026-10-10　基线提交：`62e2b11`（1.4.0 与 10-09 五笔补丁）

## 一句话

Roadstar · 引路星是本机 Claude Code 与 Codex CLI 共用的协作 skill：主席说「用 skill」，Claude 主会话按「先判用法」路由走续接 / 直接干 / 探讨 / 复盘 / 协同，Codex 审稿或执行任务，每条派出去的线带时间上限止损，文件账本保存决定与验收证据；没有独立应用、开发服务器或构建流程。

## 怎么跑、怎么测

以下命令从 `/Users/rurutia/Documents/RuruCode/Roadstar` 执行。本页命令均已核对脚本来源；本轮实跑范围见末节。

- 安装：`./install.sh`，只把 skill 软链到两家的发现目录，不管理 Claude 子代理目录；完成后重开 Claude Code 会话。
- 使用：在 Claude Code 中说「用 skill」「用 Roadstar」或 `/roadstar`，主会话按 `skill/SKILL.md`「先判用法」表自己判走哪种，开场一行报出来就跑；也可点名「开圆桌」「复盘这个项目」「全面 review」「直接调度」。
- 前置条件：codex-cli ≥ 0.160（本机 10-10 核对 0.160.0）、ChatGPT 账号登录、Claude Code Max；Python 脚本只用标准库，Shell 脚本使用 Bash。
- 额度读数：`python3 skill/scripts/quota-status.py`；机器读取加 `--json`。不发送模型推理请求，但会启动 CLI 子进程、使用临时目录并查询账号额度。
- 全量回归：`bash skill/scripts/tests/run.sh`。自动把两家 CLI 替换成本地桩，不联网、不调用真实模型；会创建临时文件与子进程，结尾输出 `PASS <数量> checks`（10-10 实跑 PASS 32）。
- 局部检查：见各模块。测试脚本没有模块筛选参数，局部检查不能替代全量回归。
- 改动后的项目规定：更新 `CHANGELOG.md`，运行桩测试及 `./install.sh`；改了模块入口、接口、测试命令或规矩，同一提交更新本页那一节；踩了新坑当天进 `division-of-labor.md` 第 15 节或项目 `_common.md`。

源码入口是 `skill/`；`docs/` 保存本仓库升级材料。实际协作场次落在**被协作项目**的 `docs/roadstar/<日期>-<slug>/`，不要把本仓库升级记录当成所有项目的运行日志。

## 流程与调度契约

- 管什么：先判用法路由，探讨／复盘／协同的流程，开场一行与模型默认值，拆活与分配，议题处置，停机、定稿与止损条件。
- 入口：`skill/SKILL.md`、`skill/references/modes.md`（含续接）、`skill/references/division-of-labor.md`、`skill/references/ledger-format.md`、`skill/references/models.md`。
- 对外接口：skill 的 `name`／`description` 触发契约（含「用 skill」「全面 review」）；开场一行的固定格式（SKILL §0 第 3 点）；场次文件 `brief.md`、`plan.md`（§10 拆分表列头见 plan-template）、`ledger.md`、`rounds/`；项目级 `docs/roadstar/_common.md`。
- 依赖：额度探针、审稿及执行模块；vela 的 `references/ui-acceptance.md`；被谁用：Claude 主会话、Codex 执行者与验收者。
- 怎么测：无独立文档契约测试；人工对照模板、流程与脚本，配套回归用 `bash skill/scripts/tests/run.sh`。
- 规矩：按路由表取第一条命中；拆活和分配只由 Argo 做，Dex 只讨论、执行、复核；实现交 Codex，不派 Claude 子代理；每条线带时间上限，两轮不收敛第三轮 Argo 查根因写方案；有界面的活按 vela 界面验收标准亲验；议题有证据、决定进账本；任务书写模块名并引用 `_common.md`；入口、接口、测试或规矩变更同步更新地图。
- 细节：`skill/references/plan-template.md`、`minutes-template.md`、`task-brief-template.md`、`project-map.md`、`pro-stage.md`；`division-of-labor.md` §15 教训表、§16 常驻边界文件（均相对 `skill/references/`）。

## 额度探针

- 管什么：并行查询 Claude／Codex 额度，归一化窗口、套餐、重置卡与 credits，计算「宽／正常／紧／空」及两次确认换档。
- 入口：`skill/scripts/quota-status.py`、`skill/scripts/tests/bin/codex`、`skill/scripts/tests/bin/claude`。
- 对外接口：`python3 skill/scripts/quota-status.py [--json] [--prev <上次JSON>]`；JSON 含 `claude`、`codex`、`note`，两家均不可用时退出码为 2。
- 依赖：Claude 控制协议 `get_usage`、Codex app-server `account/rateLimits/read`；被谁用：开场一行、拆活前复读及 `dex-exec.sh`。
- 怎么测：`PATH="$PWD/skill/scripts/tests/bin:$PATH" python3 skill/scripts/quota-status.py --json` 使用本地协议桩做读数冒烟；边界、滞回与失败清理在全量桩测试中。
- 规矩：不发送推理请求、不输出账号身份；Codex 实时读取失败才降级到本地 rollout，Claude 不用该降级源；无数据不能当额度充足。
- 细节：`skill/references/division-of-labor.md` §2–4；状态由调用方保存完整 JSON，探针不持久化读数，但会使用临时目录。

## Codex 审稿

- 管什么：生成逐轮请求、方案快照与 diff，调用只读 Codex 输出结构化审稿，再渲染成人可读文本。
- 入口：`skill/scripts/dex-review.sh`、`skill/scripts/render-review.py`、`skill/references/dex-review-prompt.md`、`skill/references/dex-review.schema.json`。
- 对外接口：`bash skill/scripts/dex-review.sh <场次目录> [--model M] [--effort E] [--root DIR] [--full] [--dry-run]`；输入须有 brief／plan／ledger，产物为 `rounds/rN-*`。
- 依赖：Codex CLI、Bash、Python、diff 与审稿 schema；被谁用：流程内环及主会话账本整理。
- 怎么测：`bash skill/scripts/dex-review.sh docs/2026-10-04-dispatch-upgrade --root "$PWD" --dry-run` 检查请求拼装、不调用模型；仍会创建 rounds 目录及临时文件，不适用于只读沙箱。
- 规矩：默认 `gpt-6-astra/high`、只读沙箱、关闭 fast_mode；PASS 的逐项清单与零阻塞要求属于审稿契约，脚本不会完整替主持人判定定稿。
- 细节：`skill/SKILL.md` §3–7；渲染命令 `python3 skill/scripts/render-review.py <审稿JSON> [--round N] [--from Dex]`；脚本默认只发送第二轮起的 diff 与筛选账本。

## 任务执行与验收

- 管什么：派发单份任务书、时间上限止损、保存请求与结果、后台状态及续接；Codex 实现，Claude 主会话跑命令核验或独立 Codex 只读会话复核。
- 入口：`skill/scripts/dex-exec.sh`、`skill/references/division-of-labor.md`、`skill/references/task-brief-template.md`。
- 对外接口：`bash skill/scripts/dex-exec.sh <场次目录> <任务号> --model M --effort E --brief FILE --max-minutes N`；支持 `--write`、`--resume`、`--detach`、`--status`、`--force`、`--dry-run`；到上限脚本 TERM 十秒后 KILL，退出码 124，meta 记 `max_minutes`／`timed_out`。
- 依赖：Codex CLI、额度探针及 Claude 主会话验收命令；被谁用：流程调度；产物为 `exec-T*.md`、请求副本、`.meta`、`.pid`、`.exit` 与日志。
- 怎么测：`bash skill/scripts/dex-exec.sh docs/2026-10-04-dispatch-upgrade T99 --model gpt-6.1-sol --effort high --brief docs/2026-10-04-dispatch-upgrade/brief.md --root "$PWD" --max-minutes 120 --dry-run`，只打印命令、路径和「时间上限：120 分钟」，不查额度、不执行任务、不写产物（10-10 实跑）。
- 规矩：模型／强度／任务书必填，默认只读；派活一律带 `--max-minutes`（常规 120、难活 240、窄回归 60），被停掉的线不自动重派，Argo 先诊断；额度「空」退出 3，探针失败则警告后继续；重复派发保留请求快照；旧锁不自动清理；执行者不提交；常规实现／取证用 6.1 Sol，难活用 Astra；审查人和执行方型号不同，钱、权限、迁移类由 Claude 主会话核验实际状态，有界面的活 Argo 亲自看截图走任务。
- 细节：`skill/references/division-of-labor.md` §8–11、§15–16；独立 Codex 复核不续接执行会话，`-s read-only`，由 CLI 的 `-o` 保存报告；浏览器／模拟器由主会话或具备环境的 Codex 核验。
