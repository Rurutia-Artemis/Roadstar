## 1 主席这个人和他的写作规范

- 主席是产品负责人，不看代码，看结论、要拍板的事和真实数字。他在日本，时间一律用 JST。
- 写给主席看的一切（面板、纪要、完工报告、README 中文、CHANGELOG）用简体中文，代码、命令、配置键保持英文。
- 先说结论，理由跟一层；默认写段落，一段一个意思；并列、步骤、比较才用列表，不嵌套；一条回复里加粗最多一处；不用装饰性 emoji。
- 禁止：破折号；「不是……而是……」「X，不是 Y」这类翻案句；「值得注意的是 / 简而言之 / 总而言之」这类路标；「赋能 / 抓手 / 闭环 / 底层逻辑 / 颗粒度」这类大词；自造复合标签和内部黑话（说人话，仓库里的叫法要提先翻成人话）；不编没来源的数字。并列最多两三项，相邻两句不用同一副骨架。
- 区分确定事实、判断和未知；没跑过说没跑过；测试结果写「N 条全部通过 / 挂了 M 条」，不写「全绿」。
- 不说「我不会做什么」「什么没变」，除非是风险点。
- 中文 README 的叙述段用大耳朵口吻（真实使用时长开场、「解决了我 N 个问题」逐条兑现、缺点用「不是特别的…」并自限收尾、分人群建议、「希望对大家有一定的参考价值」）；参考段（安装、给 AI 的安装步骤、目录、声明）干脆准确。英日 README 按 cardestiny 风格指南 L1（英文不用 em dash、不堆三连形容词、不加粗当小标题；日文不用中黑「・」三连、不过度用「あなた」、不用「〜ではなく」翻案）。
- Roadstar 对外的定位口径（主席 10-14 推广时定）：出发点是「额度怎么分才合理」。不要写成「别让一份订阅闲着」「我是这么做的」这类教程腔或口号；标题直接写谁在干什么，例如「Fable 当大脑，Opus 和 Codex 干活」。

## 3 本机环境的硬事实（第一遍可能没注意的）

- 订阅读数：`quota-status.py --json`；Claude 有 5 小时窗、周窗、Fable 单列；Codex 有周窗（ChatGPT Pro 当前没有 5 小时窗，所以 5h 读不到是正常的，面板别标成故障）、重置卡张数、credits（订阅用完后才扣，单位是 credits/1M tokens，Astra 250/25/1250、Sol 50/2.5/250）。
- 额度百分点是整数，单件小活扣不到 1 个点（校准场 12 件活周窗 9% → 9%）；细粒度用 dex-exec `.meta` 的 `tokens_used` 代理，累计到百分点动了再反推。
- 实测用时：真实项目 Codex 线 5–9 分钟（含写测试），校准场标准活 1–2 分钟；设计 v1 的默认值表偏大约十倍，要按实测重定，并写明来源。
- 公开数据：同类产品都不给「预计耗时」，Roadstar 的预估用时和完成时刻是差异点，要做得诚实（标置信度、完工对账）。
- 无头会话：`claude -p --bare` 只认 ANTHROPIC_API_KEY；bare 模式下没有 WebFetch，联网要放开 Bash 用 curl；`--allowedTools` 不含 Bash 时 Bash 一律被拒。help.openai.com 和 x.ai/pricing 会拦 curl 与无头浏览器。
- Bash 工具环境是会话开始时的快照，`~/.zshrc` 新加的变量要 `zsh -i -c` 才读得到。
- Grok CLI 1.0.60 没有查额度的命令；Grok 订阅只能在 Settings → Usage 看百分比。
- macOS 上 `os.killpg` 对只剩僵尸进程的组返回 EPERM（已在测试里接住），写新测试时同样处理。
- 非仓库协作者用 `gh issue create` 不能加标签。
- 其它会话可能同时在改主仓库；主仓库 main 的工作区里有一处别的会话未提交的 `division-of-labor.md` 第 15 节三行，不在你的 worktree 里，合并时由主会话处理，你不用管。
