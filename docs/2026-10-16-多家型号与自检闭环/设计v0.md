# 多家型号接入与自检闭环 · 设计 v0（2026-10-16）

主席 2026-10-16 定的三条（已记进共享记忆）：一、不把用户填的东西直接当真，Roadstar 自己先查公开的主流模型价格和能力做对比表，再问用户的 API 价格和额度，按额度决定哪些走订阅、哪些走 API；二、默认标准先按公开评测排名和已知能力接入，之后按日常使用和回传数据持续调整；三、打分系统由 Claude 自己持有、回传给自己看、自己迭代，不传 Google 文档，不让主席介入；主席每周说一句「可以迭代了」，Claude 据回传数据更新分工表并发新版本。

这条改掉了 `社区数据回传.md` 第 7 节和 `escalation-and-learning.md` 第 6 节里「社区表经主席拍板后写进 SKILL.md」的规矩：改成 Claude 按门槛自动调表、发版，周报只给主席看结论。

## 已经有的（不重做）

- 回传链：`telemetry.py` 开场问一次、完工时按 12 个白名单字段传到公开仓库 `roadstar-data` 的 Issue，Action 校验加标签，每周日自动汇总成 `community-table.json`。
- 本机战绩：每条线 `.meta`（class、model、effort、outcome、done_items、minutes、quota_delta、escalated_*），`dispatch-stats.py` 按「类别 × 型号 × 强度」出表。
- 碰壁止损与升级链、起步层表（SKILL.md 第 8 节）、`models.md` 实测画像、`update-check.py` 提醒更新。
- 每周一 10:00 JST 的云端周报任务。

## 要加的五块

1. **型号登记表加「家」**：`models.md` 旁边新增 `providers.json`，每个型号一条：家（anthropic / openai / xai / deepseek / moonshot / alibaba / zhipu / minimax …）、调用方式（订阅 CLI、API）、每百万 token 输入输出价（公开价，带查证日期和来源链接）、上下文长度、公开评测分（Artificial Analysis、LMArena 等，带日期）、默认角色（取证 / 批量 / 实现 / 复核 / 审方案 / 不派）。第一版由 Claude 用 wigolo 查公开来源填，国产模型和 Grok 先按公开排名给保守角色。
2. **用户额度配置**：`~/.config/roadstar/quota.json`，开场问一次：有哪些订阅（Claude 档位、ChatGPT 档位）、有哪些 API key（只记「有没有」和家，key 本身放用户自己的环境变量，Roadstar 不存不传）、每月 API 预算上限。路由规则：订阅额度宽就走订阅；紧或空、或者这类活在 API 侧更便宜且能力够，就走 API；超预算一律不走 API。
3. **API 执行器**：`api-exec.py`，对 OpenAI 兼容接口（xAI、DeepSeek、Moonshot、阿里、智谱、MiniMax 大多兼容）统一一个入口，任务书、进度文件、`.meta` 格式和 Codex 线一样，这样回传字段不变，只多一个 `provider`。第一版只做无工具的文本任务（取证、复核、审方案、文案），有工具调用的实现类活仍走 Codex 和 Claude 子代理。
4. **打分**：`.meta` 加 `score`（0 到 1）和 `score_by`。三种来源按优先级：验收命令自动判（有检查项的线）、另一家型号评（无检查项的文本活，评分提示固定，不让同家评自家）、主席抽检（可选）。回传字段加 `score` 一项（白名单扩一个固定小数位字段，schema 升到 2）。
5. **自动迭代**：`iterate.py`，每周按 `escalation-and-learning.md` 第 6 节的门槛（往下挪：≥5 次、≥3 人、完成率 ≥90%；往上挪：≥5 次、完成率 <60% 或碰壁率 >30%）读社区表和 `providers.json`，自动改 SKILL.md 第 8 节和 `models.md`，CHANGELOG 写依据行，版本号加一，周报只写「改了什么、依据什么、没动什么」放到共享记忆。主席说「可以迭代了」时跑；没说就只出周报不改表。新型号冷启动：前 100 条只做影子跑（和现任型号各跑一遍，结果不上线只打分），分数够了才进起步层。

## 不做的

- 不传 Google 文档；不要主席逐条拍板；不存用户的 key；不传任何自由文本。

## 顺序

先 1 和 2（表和配置，一天），再 3（执行器，两天），再 4 和 5（打分与迭代脚本，两天），每步跑 `skill/scripts/tests` 加新测试，发 1.12.0。方案和拆分走 Roadstar 自己的协同模式。

## 第六块：开发垃圾自动清理（主席 2026-10-16 加）

主席原话：迭代很快，每次迭代完之前的垃圾要自动清理，不然硬盘不够用。本机实测（2026-10-16）：RuruCode 下 Mia-worktrees 34 GB、RUVO 的 14 个 worktree 8.5 GB、29 份 node_modules 共 10.2 GB、`~/.cache` 7.2 GB、`~/.npm` 3.5 GB、`~/.codex/sessions` 3.1 GB、Xcode DerivedData 1.9 GB。

- `cleanup.py`，每场完工报告后自动跑一次（可关），分三档：
  1. **场内垃圾**：本场派活用过的 worktree，分支已合并且工作区干净的，`git worktree remove` 加分支删除；工作区有未提交改动的一律不动，列出来给 Argo。`rounds/` 里只留 `.meta`、任务书、报告和进度文件，中间产物（截图、日志、补丁副本）超过 7 天删。
  2. **项目垃圾**：按项目根的 `cleanup.json` 白名单删构建产物（dist、out、.next、build、.codex-build、DerivedData 本项目目录、Playwright 截图目录），没有白名单的项目只报不删。
  3. **机器垃圾**（`--deep`，每周一次）：`~/.codex/sessions` 超过 30 天、npm 与 pip 缓存、Playwright 旧浏览器版本、Metro 缓存，以及没有分支对应的孤儿 worktree 目录（`git worktree prune` 后仍存在的）。
- 规矩：先 dry-run 列清单和预计释放的空间，第一次由主席点一次头，之后同一类自动删；任何含未提交改动或未推送提交的目录不删；删前把清单写进完工报告，删后写释放了多少。
- 数据不删：`.meta`、回传副本、Obsidian 记忆、口令文件、`.env`。
