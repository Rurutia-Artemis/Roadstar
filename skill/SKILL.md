# 圆桌 · 谈到能开工，再按模型和额度派活

开圆桌：主席、Argo、Dex 围着同一份 `plan.md` 谈到账本清零，Argo 再按主席定的模型用法把活派到两边，派完回来审。直接调度：方案已有，跳过讨论，Argo 读额度、分派、验收、交报告。

## 谁是谁

| 标签 | 是谁 | 怎么参与 |
|---|---|---|
| 主席 | 用户 | 定目标与约束，开场定这次模型怎么用，随时插话，对争议拍板 |
| Argo | Claude Code 主会话（Fable 5.1 或 Opus 5.5，账本记实际模型） | 主持、起草改稿、记账、调度、验收裁定、汇报 |
| Dex | Codex CLI（`codex exec`，走 ChatGPT 订阅） | 每轮按契约审稿；执行分给它的任务；复核对方的活。型号按任务选：Astra 最强、6.1 Sol 常规；Luna 不派活 |
| Claude 侧执行者 | 子代理 `roadstar-builder`（Opus / high）、`roadstar-builder-hard`（Opus / xhigh）、`roadstar-builder-light`（Sonnet / medium）、`roadstar-checker`（Opus / high，只读加跑命令） | 按任务书实现或验收 |
| Pro | 网页 GPT Pro（可选） | 大活起草或终审；Codex 空时的跨家审稿兜底；每趟要主席动手 |

型号、用途、强度见 `references/models.md`。名字只是发言标签，没有人设。Argo 转述 Dex 时原文照贴进账本、标明 `Dex：`，自己的回应另起一段；主席的话记进账本，效力最高。改名只改这张表。

## 什么时候开

开圆桌：新项目立项、跨模块改动、要动数据结构或公开接口、难回滚、对外发布前的方案。判据是「做错了要付出多少」，超过一天返工的都值得先谈。一小时内能做完的活直接干；只要一次第二意见走 call-codex；只要 Pro 策划走 pro-orchestrator。

直接调度：方案已有（Plan 模式产出、别处的方案文档或旧圆桌 plan），带能判定的验收标准，且有不止一件能独立验收的活，就跳过起草和内环，从第 8 节调度开始。最少文件是 brief、plan（§2 验收、§10 分工表、§11 执行记录）和 ledger（主席指令、调度记录）；主席只收开场一句和完工报告。

好处有两条。两家模型的盲区不重合，交叉审稿能抓到自审抓不到的漏洞；账本和清单把「想到哪说到哪」变成写下来、逐条清零的过程，方案完整靠制度而非记性。调度把活分到两边额度上，主席这边紧时能派的全派 Codex。代价是两边的订阅额度和时间。

## 文件

```
<项目根>/docs/roadstar/<YYYY-MM-DD>-<slug>/
  brief.md        立项：目标 / 非目标 / 约束 / 规模 / 参与配置
  plan.md         方案正文，按 references/plan-template.md 的必填槽位写；定稿后追加分工表与执行记录
  ledger.md       议题账本 + 主席指令 + 调度记录 + 停车场，格式见 references/ledger-format.md
  rounds/         每轮快照与原始记录：rN-plan.md / rN-plan.diff / rN-dex-request.md / rN-dex-review.json / pro-*.md
                  执行期：exec-T<n>-request.md（任务书）/ exec-T<n>.md（执行回复）/ .meta / -stdout.log / check-T<n>.md（验收）
```

没有仓库的任务放 `~/Documents/RuruCode/AI任务/roadstar/<日期>-<slug>/`；旧的 `docs/roundtable/` 记录照旧能读。这些文件随项目提交，是工程记录的一部分。

## 流程

### 1 立项

主席一句话说目标，Argo 写 `brief.md`。目标和约束够写出验收标准就直接起草，不等点头，brief 里的假设在纪要里列给主席；只有缺口会改变结果时才问，一次问齐，最多三个。brief 必填：目标、非目标、硬约束、规模（小 / 中 / 大）、参与配置。参与配置五项 Argo 填默认值，主席随时改：

- 模型用法。开场前跑 `scripts/quota-status.py`，读两边档位（Claude 取 5 小时窗、周窗、Fable 单列里最差的，Codex 看周窗和重置卡数）。开场句里带读数、Argo 的建议和一问「这次模型怎么用？」。问完直接往下做；主席的答复到了就生效，已派的不动、没派的重排；不答按建议。主席这一句管整场，记进账本「主席指令」。
- 审稿模型与强度。写死型号，默认 `gpt-6-astra` / high；规模大或难回滚用 xhigh；Codex 紧时 `gpt-6.1-sol` / high。一场不换审稿人。
- Pro 参不参与。规模「大」默认起草 + 终审；「中」默认只终审；「小」默认不参与。
- 节奏。默认连跑：内环一口气跑到停机条件，中间不向主席开口。主席说「每轮停一下」才逐轮。
- 熔断轮数。默认 6，Codex 紧时 3，到顶把取舍类未决项交主席，不算失败。

开场只回一句，格式固定：「圆桌开了。题目：<一句人话>。额度：Claude 本周 X%，Codex Y%，<一句判断>。我的建议：<谁做实现、谁审>。这次模型怎么用，你一句话；不答按建议，跑到有结果再来找你。」直接调度时用同一句，「圆桌开了」换成「开始调度」。有要问的就把问题接在这句后面，一次问齐。此后到停机为止不再开口。例：「额度：Claude 本周 41%，Codex 12%，都不紧。我的建议：实现给 Codex 的 Astra，界面那件给 Opus，我审。」

brief 之后主席改目标或约束，记进账本「主席指令」，两边下一轮都读到。

### 2 起草

取证（读代码、跑只读命令、查文档）在起草前一次做完，派给 Sonnet 子代理或 Codex 只读，一次发出、一次收齐；结果只进 plan 的「现状」，主会话只收结论、不读大段代码，也不分批向主席回报。

规模小、中：Argo 起草 `plan.md`，按 plan-template 的必填槽位写满，写不出的槽位标「待定 + 缺什么信息」。

规模大且 Pro 参与：先让 Pro 起草（见 `references/pro-stage.md`），Argo 把 Pro 稿整理进 `plan.md` 后，第一轮 Argo 和 Dex 各审一遍，两边的议题一起进账本。审别人的稿比审自己的狠，这是让 Pro 起草的主要收益。

### 3 内环，每轮这样跑

1. 快照并送审：`scripts/dex-review.sh <plan-dir> --model <型号> --effort <强度>`，型号和强度取自 brief。第一轮把审稿契约、brief、plan 全文、账本和主席问 Dex 的话拼成请求；第二轮起默认精简，只发 diff、账本里没解决的和上轮刚解决的议题，plan 全文只给路径让 Dex 按需读（实跑里请求大小主要看 diff，省的是重复的全文），`--full` 可切回全发。跑 `codex exec` 拿结构化 JSON。
2. 渲染：`scripts/render-review.py rounds/rN-dex-review.json` 转成可读文本，抄进账本；主席不在内环里看到它。
3. Argo 逐条处置 Dex 的议题：接受就改 plan 并在账本记「已解决（rN）+ 改了哪」；拒绝要写理由和证据；拿不准的标「问主席」。Dex 给了可复现的反例（命令、行号、输出），先在本机复现再改；改出来的判定规则用同一批反例跑一遍再记已解决，凭记忆写的规则会被连判两轮无效。同一条议题第二次被拒，或 Dex 第二次判 Argo 的解决无效，自动变「争议」。范围外的建议进停车场，主席定去留。
4. Argo 也审 Dex：Dex 提出的替代方案和补充，Argo 按同一清单回评，不是照单全收。
5. 更新账本状态行，按第 4 节判停；没停就直接进下一轮，不向主席开口。
6. 主席插话（任何时候）：指令记进「主席指令」；主席直接问 Dex 的话写进 `rounds/r(N+1)-chair-to-dex.md`，下一轮原样带给 Dex，Dex 在 `reply_to_chair` 里答，答复进下一份纪要。

Dex 的「同意」不算数：PASS 必须清单逐项打勾且零阻塞项；阻塞项必须带证据（文件位置、命令输出或文档）。从第二轮起 Dex 只审 diff 和开放议题，不重翻已定项，除非能证明结论是错的。

### 4 什么时候停

停机看账本，不看轮数。每轮处置完，Argo 按下面顺序判断，命中一条就停：

| 条件 | 判定 | 动作 |
|---|---|---|
| 争议 | 账本里有「争议」或「问主席」未清 | 事实类争议（谁对谁错能靠证据定）Argo 先跑测试、读代码取证，证据定了就按证据改、账本记「争议（事实类）→ 证据支持谁」，不用停；取舍类（要什么舍什么）停下来，列双方理由请主席裁决 |
| 收敛 | 本轮零新阻塞项，开放阻塞项为零，且 Argo 处置后 plan 无实质改动（`rN-plan.diff` 为空或只有措辞） | 定稿候选 |
| 只剩小意见 | 开放项和本轮新项都只有「小意见」 | 定稿候选，小意见列在 plan 末尾当可选项 |
| 主席说停 | 任何时候 | 按主席说的办，账本记「主席终止」 |
| 熔断 | 轮次到 brief 里的上限 | 停。事实类未决项 Argo 自己用证据了结，只把取舍类交主席；不自动定稿 |

都没命中直接进下一轮。命中任何一条 Argo 才开口，开口只交纪要。

### 5 纪要：内环静默，停机才开口，写给不看代码的人

内环期间 Argo 不向主席播报进度、不解释正在做什么；取证、起草、每轮送审与处置都只落到文件和账本。系统催促回话时只回一行「圆桌进行中，第 N 轮」，不带内容。

命中停机条件后 Argo 交一份纪要，这是主席看到的全部。主席不看代码、不认识账本代号，纪要是写给他的，按下面的顺序写，模板与例子见 `references/minutes-template.md`：

1. 结果一句：定了可以开工 / 还差一件事 / 卡住了要你选。
2. 商量出来的方案：三到五句大白话，讲清做成什么样、怎么做、怎么算做完。
3. 讨论改了什么：只挑影响结果的，最多三条，句式「原来打算…，Codex 指出…，改成…」；其余一句带过（「另外还修了七处细节」）。
4. 你要做的：每件一句，先给选项再给建议，能一个字答。只问主席能判断的事：做不做、花多少、要什么舍什么；技术细节 Argo 自己定，纪要里一句带过。不问分工；谁做什么直接写在第 5 段。
5. 谁做什么：人话任务名 + 谁 + 大概多久，「谁」按 minutes-template 的称呼表写，开头一句说主席定的模型用法；不写代号不写文件名。
6. 细节在哪：一行路径。

硬规矩：纪要里 Argo 自称「我」，Dex 写「Codex」，Pro 写「网页 Pro」，Argo / Dex 这些标签只在账本和文件里用；不出现议题编号、严重度标签、字段名、命令、工具名，专有名词要用就在括号里解释一次；写完自检，一个没看过代码的人能不能只靠它知道结果、谁做什么、要答什么，不能就重写。逐轮模式的每轮汇报同一配方。

### 6 定稿，可以开工的门槛

同时满足才算定稿：账本无争议、无待答问题；plan 必填槽位全部有内容且验收标准可判定；命中「收敛」或「只剩小意见」；Pro 终审（若参与）的阻塞项已清；主席说「定稿」。Argo 在 plan 顶部写 `状态：定稿 <日期>`，账本写终态计数。

### 7 终审（Pro 参与时）

定稿候选交 Pro 看一遍，只收阻塞项和建议项，进账本走同一套处置。通道和请求模板见 `references/pro-stage.md`。Pro 提的争议同样交主席。

### 8 调度

派活前再跑一次 `scripts/quota-status.py`。每件活判四点：难度（难、中、易）、验收条件（命令行能验，还是要浏览器、模拟器、本地服务、真机）、执行环境（开发本身就要浏览器、构建、起服务、联网的整件留 Claude 侧；只有验收要的 Codex 写、Claude 侧验；真动工作区外那一步只能 Argo 或主席）、上下文（离不开主会话的先写进任务书）。多条命中按顺序取第一条：主席的硬话 > 执行环境 > 验收条件 > 难度 > 额度方向。再查 `references/division-of-labor.md` 的表，在主席定的方向里挑型号和强度；不照表派就在理由栏写一句。

结果写进 plan §10 分工表（列头见 plan-template，执行方写到型号·强度）。主席的硬话入账本，压过额度；硬话和额度撞上时在纪要里报一句冲突，不默默照做也不默默降级。定稿纪要直接写谁做什么、为什么这样排，不再问「按建议还是全给谁」。

### 9 执行与验收

- 每件活一份任务书（`references/task-brief-template.md`），派给谁都能做。
- Codex 任务：`scripts/dex-exec.sh <plan-dir> T<n> --model … --effort … --brief …`，默认只读，要改文件加 `--write`，长任务加 `--detach`，返工用 `--resume <session id>`，新会话接手先 `--status`。Claude 任务：Agent 工具调 `roadstar-builder` / `roadstar-builder-hard` / `roadstar-builder-light`。
- 并行任务各开 worktree（子代理加 `isolation: worktree`）；合并由 Argo 按依赖顺序做，合完跑一次全量验收；大搬运类先单独落地再开并行。
- 验收分级：易的执行方自测、Argo 读 diff；中和难的换一家跑证据（`roadstar-checker` 或 Codex 只读）；钱、权限、迁移类不接受同家验收；改完再验只在改到同一处逻辑时做。验收标准来自 plan，不临时降标，证据写进 §11。
- 失败上限：一件活执行两次、改派一次，第三次 Argo 接手或交主席，每次入账。改派带上已有 diff、验收输出和 worktree 路径；不越过主席定的方向，要跨到另一边先问一句。
- 额度到顶或读数进「空」：按梯子走（降一档强度 → 并行改串行 → 不急的挂到重置后 → 问主席刷不刷重置卡 → 停），记进调度记录；成本按派活前后的读数差也记在这里，完工报告写一行。
- 执行期静默；全部通过后在 plan 追加执行记录、写共享记忆、交完工报告（第三次开口，配方见 minutes-template 末尾）。

## 纪律

- 内环与执行期静默：过程只进文件与账本，主席只在停机时收到纪要；被系统催促只回一行。
- 主会话只产出四样：brief、plan 改稿、任务书、裁定。Argo 自己打开源文件改代码，就等于漏写了一份任务书。
- 转述不加工：阻塞和争议项贴 Dex、Pro 的原话并标明谁说的，贴进账本，其余给要点；Argo 的判断另写。软化对方的批评等于篡改账本。
- 证据先于立场：阻塞项要证据，拒绝要理由；事实类争议 Argo 取证了结，取舍类交主席。
- 范围不悄悄涨：范围外建议一律进停车场。
- 密钥不进 prompt：喂给 Dex 和 Pro 的内容等于发给外部服务。
- 不加 `--dangerously-*`；审稿和复核用 `-s read-only`，执行才 `--write`；真动工作区外的那一步（/Applications、LaunchAgent、Obsidian、生产）不派 Codex 沙箱，Argo 或主席做，脚本可以别人写。
- 账本是唯一真相：主席的裁决、双方的让步都要落到 ledger.md，调度记录也在账本，聊天里说过不算。
