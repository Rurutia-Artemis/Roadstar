# Roadstar · 引路星：先看面板，再谈、再派、再审

主席一句「用 skill」，Argo 先贴一张面板（接了几家、各剩多少、本项目怎么分、用哪种策略），再按路由判这次走哪种用法，开场一屏说完就跑。探讨：主席只说构思，两家围着同一份 `plan.md` 谈到能落地。复盘：两家各读一遍现有项目，交叉审出不足和先做的三件事。协同：方案已有，Argo 拆活、分型号、定审查人，派活、验收、交报告。拆活和分配只由 Argo 做；Dex 只在讨论环节提意见，在执行环节干活和复核。每一屏的数字都来自脚本输出，Argo 不手填。

## 谁是谁

| 标签 | 是谁 | 怎么参与 |
|---|---|---|
| 主席 | 用户 | 定目标与约束，开场定策略，随时插话改模型或分工，对争议拍板 |
| Argo | Claude Code 主会话（Fable 5.1 或 Opus 5.5，账本记实际模型） | 主持、起草改稿、记账、拆活与分配、排期、验收裁定、汇报 |
| Dex | Codex CLI（`codex exec`，走 ChatGPT 订阅） | 讨论环节按契约审稿、提意见；执行环节做分给它的活、复核对方的活。不拆活、不分配、不做决定。型号按任务选：Astra 最强、6.1 Sol 常规（要 codex-cli 0.160 以上）；Luna 还没实测，「试新型号」开关开时在简单活里试用（见 models.md） |
| Claude 子代理 | Claude Code 的 Agent 工具，型号 Haiku / Sonnet / Opus / Fable（主席 2026-10-14 定四层按活常驻） | 和主会话共用同一份 Claude 额度，能并行，中间上下文不进主会话。Haiku 5.5 常驻接取证和机械批量；Sonnet 常驻接 Codex 写的中、难活的跨家只读复核，Codex 紧或并行线多时接规格清楚的实现；Opus 接难活、根因、样张，和 Astra 按额度二选一；Fable 平时只做主会话，同一问题两轮没收敛或审方案要最强一层时才派。拆活、分配、裁定仍只在主会话 |

| Pro | 网页 GPT Pro（可选） | 大活起草或终审；Codex 空时的跨家审稿兜底；每趟要主席动手 |

## 先判用法（主席说「用 skill」时的路由，按顺序取第一条命中）

| 现场情况 | 走哪种 | 讨论轮数 |
|---|---|---|
| 项目里有没完工的 roadstar 目录（plan 没写「完工」，账本有没派或没验收的活） | 续接那场：读账本接着干，不新开 | 不新开 |
| 一小时内能做完，或已定位到一处的小改 | 直接干，不进 skill，回一句「这件小，直接干了」 | 0 |
| 主席只有构思；新项目；要动结构、数据或公开接口；难回滚；对外发布前 | 探讨 | 熔断 3，规模大 4（策略会改，见 §8） |
| 现有项目没方案，主席想知道哪里不足；或说「全面 review」「全部排查」 | 复盘（尺子选产品层或代码层） | 两家各读一遍，审合并稿熔断 1 |
| 方案已有（Plan 模式产出、探讨或复盘的结论、主席口述清楚到能写验收标准） | 协同 | 0 |

判据是「做错了要付多少」：返工超过一天的先探讨。拿不准按更保守的一档。主席明说走哪种就走哪种。

## 三种用法

探讨：§0 面板 → §1 → §1.5 功能地图（两家把功能想全，主席分档；纯工程改动跳过）→ §2 到 §5（纪要带排活表）→ 主席说开工 → §8 → §9 → §10。讨论阶段用最强的（总调度 Fable 或 Opus，审稿按策略表默认 Astra / high，大活加网页 Pro），开场说明写清要扣几点、花多久。默认三轮，规模大四轮，收敛了提前停。

复盘：§0 面板 → §1（brief 写尺子）→ 两家各自只读取证、各出不足清单 → Argo 合并 → §3 审合并稿（熔断 1）→ §5 纪要：不足清单按严重度 + 先做的三件事 + 排活表 → 主席选哪几件 → §8。尺子两种：产品层（能不能上架、收费、交付）和代码层（逐模块找 bug 与隐患，Codex 侧按模块并行派只读线）。

协同：§0 面板 → §8 排活表 → §9 → §10 完工报告。排活表报给主席一次就派，主席改哪条就停那条重派。细节见 `references/modes.md`。

一小时内能做完的活直接干；只要一次第二意见走 call-codex；只要 Pro 策划走 pro-orchestrator。

好处有两条。两家模型的盲区不重合，交叉审稿能抓到自审抓不到的漏洞；账本和清单把「想到哪说到哪」变成写下来、逐条清零的过程，方案完整靠制度而非记性。实现默认交 Codex；Claude 四个型号按活常驻；每条线碰壁就停，做完的收下，剩下的交高一级型号补全；每次派活的战绩都记下来，分工表靠社区数据变准，用时预估靠本机记录变准。代价是两边的订阅额度和时间，面板和排活表把这个代价先算给主席看。

## 使用步骤：每一屏长什么样、什么时候问、沉默等于什么

一场只出一张面板，放在开场；之后每一屏只写变了的。每一屏都有默认答案，主席沉默就按默认跑。必须等答复的点只有四处：功能地图分档、纪要里开不开工、取舍类争议、策略是质量优先而额度不够。各屏的完整例子和脚本命令在 `references/screens.md`。

| 屏 | 什么时候出 | 要不要答 | 沉默等于 |
|---|---|---|---|
| 接入与额度面板 + 策略一问 + 本项目分配预览 | 开场，一条消息 | 策略答一个词或回车 | 自动分配（或 quota.json 的默认） |
| 探讨开场说明 | 探讨用法，紧跟预览 | 看一眼 | 按默认轮数和型号跑 |
| 功能地图分档 | 探讨，内环前 | 要答，只改不同意的 | 按预填分档 |
| 纪要 + 排活表 | 停机后 | 要答，开不开工 | 不开工 |
| 执行中进度 | 主席问、系统催促、预计完工变动超过 30 分钟、额度降档 | 看一眼 | 继续 |
| 完工报告 | 全部验收后 | 看一眼 | 结束 |

### 0 开场：面板、策略一问、分配预览（一条消息）

1. 按顺序跑：`scripts/quota-status.py --json` 存成 `rounds/probe.json`；`scripts/quota-estimate.py --probe rounds/probe.json [--session 探讨 --size <规模>]` 存成 `rounds/panel.json`；`scripts/panel.py --estimate rounds/panel.json --usage <用法> --title <题目> --instructions <项目指令一句>`；另跑 `scripts/update-check.py`、`codex --version`、`scripts/telemetry.py status`。`codex --version` 跑不出来或未登录就进单家模式（面板会写）。
2. 把 `panel.py` 的输出原样贴出，一个数字都不改。面板第一行直说接了几家；Grace 单列为调研协作方；读不到的家写「读不到（原因）」并按紧处理；系数没校准的件数带「约」并同时给百分点。面板末行「要改说一声，不改我就跑」之前那行就是策略一问：主席回车或不答就是自动分配（quota.json 设了默认就是那个），说「质量优先」「省着用」「赶时间」只管本场，记进账本「主席指令」。
3. 面板下面紧跟「本项目分配」预览（类别 → 型号，按策略表和额度方向实例化，最后一行写压过默认的项目指令），探讨用法再加三行「探讨阶段用最强的」说明（型号、预计扣几点几件、预计用时）。
4. 这条消息里还要说的：这次走哪种用法、为什么、题目一句人话；有新版本加一句「说『更新 Roadstar』就拉到最新」；`telemetry.py status` 显示「还没问过」就把回传同意问一次（问法照 `docs/社区数据回传.md` 第 1 节，默认不开）；quota.json 不存在时面板会提示「填额度」。要问的事合成一次 AskUserQuestion 问齐，没有要问的就说完直接往下。
5. 主席说「填额度」就跑 `scripts/quota-config.py set <键> <值>`；说「关掉回传」「打开回传」「回传了什么」跑 `telemetry.py disable / enable / send --dry-run`；说「还能派多少活」「额度面板」就只重贴面板。
6. 续接和协同不重出全面板，用 `panel.py --compact` 的两行（上一场还剩几件、两边读数、策略、预计完工）。

### 1 立项

主席一句话说目标，Argo 写 `brief.md`。目标和约束够写出验收标准就直接起草，不等点头，brief 里的假设在纪要里列给主席；只有缺口会改变结果时才问，一次问齐，最多三个，问题并进 §0 那次提问。建场次目录时顺手跑 `scripts/dispatch-stats.py --register <项目根>`。brief 必填：目标、非目标、硬约束、规模（小 / 中 / 大）、参与配置。参与配置六项 Argo 填默认值，主席随时改：

- 策略。抄 §0 主席答的那个；没答写「自动分配」。
- 模型用法。抄分配预览。
- 审稿模型与强度。按策略表「审方案」那格，默认 `gpt-6-astra` / high；规模大或难回滚 xhigh；单家模式写「Fable 子代理（同家）」。一场不换审稿人。
- Pro 参不参与。规模「大」默认起草 + 终审；「中」默认只终审；「小」不参与；省着用和赶时间不参与；单家模式不参与。
- 节奏。默认连跑：内环一口气跑到停机条件，中间不向主席开口。
- 熔断轮数。探讨 3，规模大 4，复盘 1；按策略加减（质量优先 +1、省着用 −1，最少 1）。到顶把取舍类未决项交主席，不算失败。

开场那条消息之后到停机为止不再开口。brief 之后主席改目标或约束，记进账本「主席指令」，两边下一轮都读到。

### 1.5 功能地图（探讨专用，先想全要做什么）

新产品、新 App、新网站、带界面的新模块，起草工程方案之前先做功能地图；纯工程改动跳过，开场写明。Argo 写骨架，Argo 和 Dex（策略表「功能地图」那格，默认 Astra / high，只读）各自按十个角度独立发散，Argo 合并去重，Dex 再审一次合并稿（赶时间跳过这步），Argo 预填「这版必做 / 下版再说 / 不做」交主席只改不同意的。这是探讨里唯一一次在内环前开口；开口时顺带一行实际数「功能地图花了 N 分钟，Codex +N 点」。细则见 `references/feature-map.md`。对标产品、官方规范这类要查外部资料的，写成任务书交 Grace，不占本机额度。

### 2 起草

取证从项目地图开始：先读 `docs/模块地图.md`（规格见 `references/project-map.md`）。没有地图或地图和代码对不上，先派一件活建或补地图（Codex 6.1 Sol / medium 只读起草，Argo 核对后提交），算本场第一件活。取证（读代码、跑只读命令、查文档）在起草前一次做完，按策略表「取证」那格派（默认 Haiku 只读，Claude 紧或读不到时 6.1 Sol / medium），一次发出、一次收齐；结果只进 plan 的「现状」。规模小、中：Argo 起草 `plan.md`，按 plan-template 写满，写不出的槽位标「待定 + 缺什么信息」。规模大且 Pro 参与：先让 Pro 起草（`references/pro-stage.md`），Argo 整理后第一轮 Argo 和 Dex 各审一遍。

### 3 内环，每轮这样跑

1. 快照并送审：`scripts/dex-review.sh <plan-dir> --model <型号> --effort <强度>`，型号和强度取自 brief。第二轮起默认精简，只发 diff、账本里没解决的和上轮刚解决的议题，`--full` 可切回全发。单家模式不跑这个脚本：Argo 自己快照、diff，按同一份审稿契约（`references/dex-review-prompt.md`）拼请求，用 Agent 工具派 Opus 子代理审，输出符合 `references/dex-review.schema.json` 的 JSON，`render-review.py … --from Opus`，议题前缀 `O`。
2. 渲染：`scripts/render-review.py rounds/rN-dex-review.json`，抄进账本；主席不在内环里看到它。
3. Argo 逐条处置：接受就改 plan 并记「已解决（rN）+ 改了哪」；拒绝写理由和证据；拿不准标「问主席」。Dex 给了可复现的反例先在本机复现再改。同一条议题第二次被拒，或 Dex 第二次判解决无效，自动变「争议」。范围外的进停车场。
4. Argo 也审 Dex 的替代方案和补充，按同一清单回评。
5. 更新账本状态行，按 §4 判停；没停直接进下一轮，不向主席开口。
6. 主席插话（任何时候）：指令记进「主席指令」；主席直接问 Dex 的话写进 `rounds/r(N+1)-chair-to-dex.md`，下一轮原样带给 Dex。

Dex 的「同意」不算数：PASS 必须清单逐项打勾且零阻塞项；阻塞项必须带证据。从第二轮起 Dex 只审 diff 和开放议题。

### 4 什么时候停

停机看账本，不看轮数。每轮处置完按顺序判断，命中一条就停：争议（取舍类停下交主席；事实类 Argo 取证了结不停）；收敛（本轮零新阻塞、开放阻塞为零、plan 无实质改动）；只剩小意见；主席说停；熔断（到 brief 的上限，事实类自己了结，只把取舍类交主席，不自动定稿）。都没命中直接进下一轮。细则见 `references/ledger-format.md`。

### 5 纪要 + 排活表：内环静默，停机才开口，写给不看代码的人

内环期间不播报进度；系统催促回话时只回一行「圆桌进行中，第 N 轮」。命中停机条件后 Argo 交一份纪要，这是主席看到的全部，按 `references/minutes-template.md` 写：结果一句；方案三到五句大白话；这版要做的功能（做了功能地图时）；讨论改了什么，最多三条；你要做的，第一条固定是「开不开工；排活表改不改哪条」；排活表；细节在哪。

排活表由脚本出，不手排：Argo 先把拆分表写进 plan §10（列头见 plan-template，每件写类别、执行方、审查人、依赖），再跑 `scripts/schedule.py --plan plan.md --strategy <策略> --probe rounds/probe.json --start <开工时刻>` 存 `rounds/schedule.json`，把它的 markdown 原样贴进纪要。表的形状固定：表前一行写策略、额度方向和置信度；每件一行七列（事、给谁 · 强度、为什么、预估、预计完成、审查人、依赖）；超过 8 件只列前 8 件，其余折成「另 N 件同类」；表后四行总账（线上工时合计与 Argo 用时、并行线数、关键路径；预计全部完工时刻，从主席说开工起算，等点头的时间不算；额度预计；「开工就按表派，改哪条说一声」）。「预计完成」是该件验收完的时刻，含复核和 Argo 验收。

硬规矩：纪要里 Argo 自称「我」，Dex 写「Codex」，Pro 写「网页 Pro」，Grace 写「Grace」；代号、命令、工具名不进纪要；写完按 minutes-template 的要求自检。

### 6 定稿，可以开工的门槛

同时满足才算定稿：账本无争议、无待答问题；plan 必填槽位全部有内容且验收标准可判定；命中「收敛」或「只剩小意见」；Pro 终审（若参与）的阻塞项已清；主席说「定稿」或「开工」。Argo 在 plan 顶部写 `状态：定稿 <日期>`，账本写终态计数。

### 7 终审（Pro 参与时）

定稿候选交 Pro 看一遍，只收阻塞项和建议项，进账本走同一套处置。通道和请求模板见 `references/pro-stage.md`。

### 8 拆活与分配（Argo 做，Dex 不参与）

派活前再跑一次 `scripts/quota-status.py --json`。Argo 读方案，拆成能独立验收的活，写进 plan §10 拆分表：模块、目标、能失败的完成线、执行环境、类别、执行方（型号·强度）、上限、审查人、依赖。拆法：一份一个目标、两小时内做完；按文件归属切线，共享中枢只归一条线；要模拟器的线同时最多两条；每件判四点（难度、验收条件、执行环境、上下文，判法见 division-of-labor 第 5 节），多条命中按顺序取第一条：主席的硬话 > 执行环境 > 验收条件 > 难度 > 策略 > 额度方向。

执行方有两家六个型号。Codex 梯子：6.1 Sol（规格清楚的活）→ Astra（难活）。Claude 四层：Haiku 5.5（取证、机械批量）→ Sonnet（跨家只读复核、规格清楚的实现）→ Opus（难活、根因、样张）→ Fable（只在两种情况派：同一问题两轮没收敛，第三轮查根因写方案；审方案要最强一层）。先分两类活：

- 常驻活不看 Codex 额度：取证和机械批量默认 Haiku，Codex 写的中、难活默认 Sonnet 只读复核。Claude 周窗或 5 小时窗读到紧、空或读不到，这两类退回 Codex（6.1 Sol / low 或 medium 只读，Codex 另一型号复核）。
- 实现按额度定方向：Codex 宽或正常，或有重置卡可刷，实现走 Codex 梯子；Codex 紧或空且 Claude 正常或宽，走 Claude 梯子；同时在跑的 Codex 线已有三条以上时，规格清楚的新活可以分给 Sonnet 并行，理由栏写一句。两边都紧按 `references/strategies.md` 的降级顺序走。

起步层只按下表，这张表是所有人共用的一份，只随新版本更新（依据是社区回传数据的汇总，Claude 按门槛自动改表发版，主席每周说一句「可以迭代了」，10-16 定；本机记录不单独改本机起步层）。策略只在表上做运行时偏移，不写回表：自动分配就是这张表；质量优先、省着用、赶时间每类怎么挪见 `references/strategies.md`。碰壁就停、只把没过的检查项交高一级补全，升级链、停的信号和记账字段见 `references/escalation-and-learning.md`。主席的话压过方向。实测依据在 `references/models.md`：

### 9 执行与验收

- 每件活一份任务书（`references/task-brief-template.md`），引用 `docs/roadstar/_common.md` 的常驻边界，只写它没写的。一份任务书一个目标、一条能失败的完成线；写明「预计用时」（抄排活表）和上限（预计的两倍，最多不超过类型默认上限，见 estimates.md），不许直接套 120 分钟；写明「验证方式只用 X」，禁止执行方自己发明验证手段。派之前过一遍 division-of-labor 第 15 节。
- 任务书写明涉及哪几个模块（用地图里的名字）。改动碰了模块的入口文件、对外接口、测试命令或规矩，执行方在同一提交里更新地图那一节；验收方核对地图和代码一致。
- Codex 任务：`scripts/dex-exec.sh <plan-dir> T<n> --model … --effort … --class <类别> --est-minutes <预估> --strategy <策略> --brief … --max-minutes <上限>`，默认只读，要改文件加 `--write`。任何会话派 Codex 一律走这个脚本，哪怕只有一件活、不在 Roadstar 场次里；裸 `codex exec` 只留给一句话提问。到点脚本停掉 codex、退出码 124、meta 记 `timed_out=1`。
- Claude 子代理任务：用 Agent 工具派，`model` 按 §8 选 haiku / sonnet / opus，fable 只用于那两种情况并在调度记录写明；任务书同一份模板原文当提示，回复存成 `rounds/exec-T<n>.md`，`.meta` 由主会话手写（型号、起止时间、上限、est_minutes、strategy、派前后读数）。到点用 TaskStop 停。
- 调研类活：任务书放进 Google Drive「Grace × Cloud 交接 / 05-Roadstar 引路星」，按 00-约定 命名、记日志；排活表里这类活写「Grace，交回后并入」，不计入完工时刻；交回后 Argo 并进 plan 并记账。
- 有界面的活：完成线包含 vela 的 `references/ui-acceptance.md`；Argo 亲自逐张看截图、在模拟器里走核心任务。设计类的活按主席 2026-10-12 定的默认：先从 Huemo 配套编号写进任务书，方向稿 2 到 3 版由主席挑，完成线含两遍 review 与默认两遍打磨记录。
- 验收按 §8 表里的审查人做，分级与配对见 division-of-labor 第 8 节：钱、权限、迁移类由 Argo 核验实际状态。证据写进 plan §11。
- 止损：每条线派出就带 `--max-minutes`，写进度文件，Argo 用 `scripts/stall-watch.py` 盯：同一检查项连续三次失败、空转、用掉九成时间还没完，任一条命中就停，做完的收下，只把没过的项交高一级型号补全。被停掉的线不自动重派。到预计用时的一半还没有一个检查项 pass，Argo 看一眼进度文件；到预计用时还没完就停线收口，不等上限。
- 进度屏：执行期静默，只在主席问、系统催促、预计完工变动超过 30 分钟、或额度降档时出一次，只写变了的：几条在跑、几件验收完（预估几分实际几分）、哪件在哪一项上卡住、预计完工原 → 新、额度从几到几。额度降档的提醒写法固定：「<哪家> 到 <几成>，第 <几> 件从 <A> 降到 <B>，预计完工 <原> → <新>；想保质量就 <刷卡 / 等 X 时重置>，说一声我换回来。」策略是质量优先时不自动降型号，停下来问。
- 发版或交付前，Argo 在合并后的主干上亲自复跑至少一组完整验收；合并后该线 worktree 留作槽位，自建模拟器删掉，查一眼同机生产服务还活着。

### 10 完工报告

全部通过后：在 plan 追加执行记录；给每条线的 `.meta` 补齐 class、outcome、done_items、minutes、quota_delta（est_minutes 和 strategy 派时已写）；跑 `scripts/dispatch-stats.py --calibrate`（只改本机预估）；跑 `scripts/cleanup.py --project <项目根>`（默认只列不删，列出来的 worktree 和中间产物在报告里给主席看，主席点头一次后同一类可加 `--apply`）；跑 `scripts/telemetry.py send`（关闭或没问过时什么都不做）；写共享记忆；交完工报告（配方见 minutes-template 末尾）：做完了 / 做了一半；做了什么；怎么验的；预估对账（每件预估、实际、偏差，整场合计，最准和最偏的各一件，样本不到 5 条就说默认值先不动）；额度（两边读数从几到几，和排活表预计的比）；清理（删了什么、释放多少、哪些没动和原因）；没做完的；你要做的；记录在哪，回传了几条。

## 纪律

- 主席开口的点固定：开场那条消息后改不改（含策略）、功能地图分档、纪要里开不开工、中途拍板争议或质量优先下额度不够、最后收报告；其余时间静默，被系统催促只回一行。
- 面板、分配预览、排活表、进度屏、完工报告里的数字都来自脚本输出或 `.meta`，Argo 不手填、不估个大概写上去。
- 主会话只产出四样：brief、plan 改稿、任务书、裁定。Argo 自己打开源文件改代码，就等于漏写了一份任务书；例外是 §8 表里的整合小修，超过 30 行要复核。
- 转述不加工：阻塞和争议项贴 Dex、Pro、Grace 的原话并标明谁说的，其余给要点；Argo 的判断另写。
- 证据先于立场：阻塞项要证据，拒绝要理由；事实类争议 Argo 取证了结，取舍类交主席。
- 项目要模块化：上手、修改、找 bug 都从地图出发；地图跟着代码改。
- 范围不悄悄涨：范围外建议一律进停车场。
- 密钥不进 prompt：喂给 Dex、Pro、Grace 的内容等于发给外部服务；API key 只记有无，值不读、不存、不传。
- 默认不加 `--dangerously-*`；审稿和复核用 `-s read-only`，执行用 `--write`。例外只有一种：验收必须起模拟器、开端口、真点界面而沙箱做不到时，用 `-s danger-full-access`，任务书写死边界块，见 division-of-labor 第 15 节。
- 账本是唯一真相：主席的裁决、策略切换、双方的让步、调度记录都落到 ledger.md，聊天里说过不算。
- 踩了新坑当天写进 skill：现象和以后的做法进 division-of-labor 第 15 节或 `_common.md`。
