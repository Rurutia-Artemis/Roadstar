# 一页设计（任务书之前）

写模式且类别不在「取证 / 复核 / 审方案 / 补全」时要写；「批量 / 窄回归且预计 ≤60 分钟」免写。没给类别时，预计 >60 分钟要写、≤60 分钟免写，类别与预计都没给就要写。
中活只写「半页」：大小、为什么做、做完的样子、这次不做什么、哪种情况技术上跑通也算失败、只有主人能答的问题必填；跨模块另填模块表，整体性的活另填同类方案。
大活和新项目全写。存在场次目录 `design.md`，任务书用一行 `设计页：<路径>` 引用。
有「只有主人能答的问题」就一次问齐并等主人回；大活、新项目即使无问题也要给主人看并等点头。主人回「好」即全部按推荐答案。
来源：取自 obra/superpowers 的 brainstorming（为什么、反目标、两三种做法、只有主人能答的问题一次问完）和 addyosmani/agent-skills 的 spec-driven-development Phase 0 能力地图（模块表与构建顺序），均 MIT。

## 大小
<一行：中活 / 大活 / 新项目，选一个，加一句理由。>

## 为什么做
<谁遇到了什么问题，为什么现在做。>

## 做完的样子
<用户能完成什么，以可观察的结果写清。>

## 这次不做什么
<明确非目标与范围边界。>

## 哪种情况技术上跑通也算失败
<写清用户不愿意用、收益不成立或代价过大的具体情形。>

## 两三种做法和选的那种
<两三种方案的取舍、选哪种、为什么。中活可留空。>

## 同类方案
<目标是新系统 / 新项目 / 大改版这类整体性的活时必填：至少 3 条带链接的项目或产品，每条写怎么做、取什么、不取什么、许可证；查不到写「查过：关键词…，无」。非整体性的活写「跳过：理由」。>
