# 功能地图：先把「要做什么」想全，再谈「怎么做才稳」

主席 2026-10-14 定：很多人只知道主功能（「我想做个类似 X 的软件」），主功能周围有哪些设置、选项，还能衍生出什么功能，自己想不到。探讨开头先让两家模型一起把功能想全，主席分完档，再进入工程讨论。没有这一步，探讨只是在把一个不完整的东西做稳。

## 什么时候做

- 做：新产品、新 App、新网站、带界面的新模块；主席说「我想做个类似 X 的」「帮我规划功能」「还能加什么功能」。
- 跳过：纯工程改动（重构、迁移、换底座、性能、修 bug），开场一行写「功能地图：跳过（纯工程）」。拿不准就做，最多多花半小时。

## 五步

### 1 Argo 写骨架

在场次目录建 `feature-map.md`，先写这几样：

- 一句话产品：给谁、解决什么、做成什么样。
- 用户：两三类，每类一句话说他为什么来用。
- 对标：主席提到的「类似 X」，加 Argo 查到的一到三个同类产品（wigolo 查官网、应用商店页、帮助文档，`force_refresh`），列它们的主要功能和设置项，写明来源链接。
- 主功能：一到三个。
- 使用路径：第一次打开 → 完成第一件事 → 天天用 → 出了问题 → 想分享或付费。每一步一句话。

### 2 两家各自发散

Argo 和 Dex 各自独立想副功能，互不看对方的稿。Dex 用 `codex exec -s read-only -m gpt-6-astra -c model_reasoning_effort=high --disable fast_mode`，提示用本文末尾的「给 Dex 的发散请求」，把骨架原文贴进去。单家模式由一个和主会话不同型号的 Claude 子代理来想（主会话是 Fable 就派 Opus，主会话是 Opus 就派 Fable）。

两边都按这十个角度逐个过，每个角度至少写一条，确实没有就写「无，因为…」：

1. 第一次用：引导、空状态、示例数据、从别处导入
2. 天天用：快捷操作、搜索、筛选排序、批量、收藏、历史
3. 设置与选项：个性化、主题、通知开关、隐私、语言与单位、默认值
4. 出错与边界：离线、撤销、冲突、误删恢复、权限被拒、数据很多或很少
5. 提醒与留存：通知、小组件、周报、连续使用的反馈
6. 分享与协作：导出、分享图卡、多人一起用
7. 数据：导入导出、备份、多设备同步
8. 衍生功能：主功能产生的数据还能做什么（统计、趋势、推荐、AI 帮忙）
9. 收费与增长：免费和付费的边界、试用、邀请
10. 无障碍与多语言

每一条写成一行：

| 功能 | 给谁 | 达成什么效果（用户得到什么） | 挂在路径哪一步 | 成本 S/M/L | 来源（对标 / 推演） |

### 3 Argo 合并

两份合成一张表，去重，标出「两家都想到」和「只有一家想到」。两家都想到的通常是用户默认就会要的，只有一家想到的往往是亮点或者是过度设计，正好留给下一步审。

### 4 Dex 审合并稿

再调一次 Dex（同一型号、只读），只问三件事：十个角度哪个还空着或想得太浅；哪些副功能会拖累主功能体验或是过度设计；有没有对标产品都有、我们漏了的。意见进账本，Argo 逐条处置，规矩和内环一样。

### 5 主席分档

Argo 给每条预填一档并写一句理由，交主席确认。主席只改不同意的那几条：

- 这版必做：没有它主功能用起来就不爽，或成本 S 且效果明显。
- 下版再说：有价值但不影响第一版上手。
- 不做：伤主功能、过度设计、或成本远大于效果，写一句为什么。

分档结果写回 `feature-map.md`。「这版必做」进 plan §0 和 §1 的目标，「下版再说」进 §0 的路线图，「不做」进 §1 的非目标。然后才进 SKILL 第 2 节起草工程方案。

## 产出

- `feature-map.md`：骨架、合并表（带分档）、Dex 两次意见的处置。
- plan §0：一句话产品、核心路径、这版必做（每条「功能：效果」）、下版路线图、不做及理由。
- 纪要「这版要做的功能」一段（见 minutes-template）。

## 给 Dex 的发散请求

```
你是产品策划搭档，只读不改。下面是一个产品的骨架（一句话产品、用户、对标、主功能、使用路径）。
请独立想出主功能之外的副功能、设置项和衍生功能，按下面十个角度逐个写，每个角度至少一条，确实没有就写「无，因为…」：
第一次用；天天用；设置与选项；出错与边界；提醒与留存；分享与协作；数据；衍生功能；收费与增长；无障碍与多语言。
每条一行：功能 | 给谁 | 达成什么效果（用户得到什么，一句话） | 挂在使用路径哪一步 | 成本 S/M/L | 来源（对标 / 推演）。
效果要写用户能感到的变化，不写「提升体验」这种空话。不写实现方案，不排优先级。
最后单列三条你认为最能让用户用得更爽、但最容易被忽略的功能，各写一句为什么。

骨架：
<贴 feature-map.md 骨架原文>
```
