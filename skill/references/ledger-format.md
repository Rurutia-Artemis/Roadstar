## 编号与提出方

编号前缀按提出方：`D` Dex、`O` 单家模式的 Opus 子代理审稿人、`A` Argo、`P` Pro、`C` 主席。同一条议题从头到尾一个号，状态变了改状态列，不新开一行。

## 严重度

- 阻塞：不解决就不能开工。缺验收标准、方案有已知会失败的路径、影响面没写、回滚缺失都算。
- 建议：解决了方案明显更好，不解决也能开工。
- 小意见：措辞、命名、可选优化。

提出方定严重度，对方可以在处置时降级，降级要写理由；被降级的一方下一轮可以反对，反对两次成争议。

## 状态机

```
开放 ──接受并改 plan──▶ 已解决（rN）──对方下一轮判 still_open──▶ 开放（第二次即争议）
开放 ──拒绝 + 理由────▶ 开放（第二次拒绝即争议）
开放 ──标 escalate───▶ 争议（事实类 Argo 取证了结 / 取舍类交主席）
争议 ──主席裁决──────▶ 主席裁决（记 C 号）
开放 ──主席说不做────▶ 搁置
范围外 ─────────────▶ 停车场
```

「已解决」必须对应 plan 的实际改动（能在 rN-plan.diff 里找到），没有改动就不能记已解决。

争议分两类。事实类：Argo 复现对方的反例、跑命令或读代码，证据定了就按证据改，账本状态写「争议（事实类）→ 证据支持 X，已解决（rN）」，并在「争议处置记录」里写复现命令与结果，不交主席。取舍类：停，交主席裁决。判不清是哪类的按取舍类办。

## 每轮处置后的停机判定（Argo 执行，按顺序）

1. 争议待裁（取舍类）> 0 或 问主席 > 0 → 停，交主席。
2. 本轮新阻塞 = 0 且 开放阻塞 = 0 且 plan 自上轮「未变」（diff 为空或只有措辞） → 收敛，定稿候选。
3. 开放项与本轮新项全是小意见 → 只剩小意见，定稿候选。
4. 轮次 ≥ 熔断 → 停，事实类未决项 Argo 用证据了结，取舍类交主席。
5. 否则下一轮。

「plan 自上轮」由 Argo 看 `rounds/rN-plan.diff` 判断，写「未变 / 措辞 / 实质」三档。事实类争议（谁对谁错能靠证据定）Argo 取证了结，不交主席；取舍类（要什么、舍什么）直接交主席。

## 状态行怎么算

- 开放阻塞 / 开放建议：状态为「开放」的条目按严重度计数。
- 本轮新阻塞：本轮 Dex（或 Pro）新提且严重度为阻塞的条目数，不管处置结果。
- 已解决：状态为「已解决」或「主席裁决」的条目数。
- 争议待裁：只数取舍类；「争议（事实类）→ … 已解决（rN）」算已解决。
