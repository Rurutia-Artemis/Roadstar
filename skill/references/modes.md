# 三种用法的流程细节

三种用法都从 SKILL.md 第 0 节选模型开始，主席答了才往下。下面每节写触发词、进入条件、步骤、产出文件、主席在哪几步开口、模型默认值。主席在第 0 节选的和在推荐表上点的，压过这里的默认值。

## 探讨

触发词：「探讨一下怎么落地」「开圆桌」「三方讨论」「拉 Codex 一起商量」「让 Dex 审方案」。

进入条件：主席只有构思，或要做新项目、跨模块改动、要动数据结构或公开接口、难回滚、对外发布前的方案。判据是「做错了要付出多少」，超过一天返工的都值得先谈。

步骤：

1. 第 0 节选模型。
2. 第 1 节立项，写 brief。
3. 第 2 节起草 plan；规模大且 Pro 参与时先让 Pro 起草。
4. 第 3 节内环，按第 4 节判停。
5. 第 5 节纪要，带推荐分工表；第 6、7 节定稿与终审。
6. 主席说开工，答了分工那一问，进第 8 节派活，第 9 节执行与验收，交完工报告。

产出文件：brief.md、plan.md（§1–§9，定稿后补 §10 分工表、§11 执行记录）、ledger.md、rounds/ 下每轮快照与审稿记录。

主席开口：开头选模型；纪要里答分工和取舍；内环里有取舍类争议时拍板；最后收完工报告。

模型默认值：探讨阶段只列最强的几个给主席选（Fable / Opus 当总调度，Astra 审稿，大活加 Pro），真干活再按推荐表用便宜的。审稿默认 `gpt-6-astra` / high，规模大或难回滚用 xhigh；Pro 按规模参与（大：起草 + 终审，中：只终审）。

## 复盘

触发词：「复盘这个项目」「看看哪里能改进」「这个项目哪里不足」「先改什么」。

进入条件：项目已经存在，主席想知道哪里不足、先改什么，还没有具体方案。参考 RUVO 09-24 那场（RUVO 项目的 `docs/roundtable/2026-09-24-project-gaps/`）。

步骤：

1. 第 0 节选模型。
2. 第 1 节立项。brief 里写尺子：以什么为标准判断不足（例：能不能开始收费、能不能交付给客户、能不能上架）。规模按项目大小填，熔断默认 3。
3. 先看项目地图（`docs/模块地图.md`，规格见 `project-map.md`）：没有就把「建地图」算进先做的事，取证时顺手起草；有就按地图分模块取证，地图和代码对不上本身记一条不足。
4. 两家各自只读取证，读同一批东西（目录结构、测试、最近提交、README 与现有文档），一次发出、一次收齐：
   - Claude 侧：`roadstar-builder-light` 或内置 Explore 读结构、跑测试、看最近提交。
   - Codex 侧：`gpt-6.1-sol` / medium，`-s read-only`。
   - 各出一份不足清单，每条写现象 / 证据位置 / 影响 / 建议，按严重度分三档：阻塞（挡住收费、上线或交付）/ 应修 / 可改。
5. Argo 合并去重成 plan 草稿：§3 现状 = 两份清单的证据，§4 = 先做的三件事及理由；两家都提到的条目标出来，只有一家提到的保留并注明出处。
6. 第 3 节内环，Dex 审合并稿，熔断 3，按第 4 节判停。
7. 第 5 节纪要给主席：不足清单按严重度、先做的三件事、每件推荐谁做和理由。
8. 主席选开工哪几件，选中的转协同，从第 8 节派活。

产出文件：brief.md（含尺子）、`rounds/gaps-claude.md` 与 `rounds/gaps-codex.md`（两份不足清单原文）、plan.md（合并稿）、ledger.md。

主席开口：开头选模型；纪要里选开工哪几件、答分工那一问；最后收完工报告。

模型默认值：取证用便宜的（Sonnet / 6.1 Sol medium），合并和审合并稿用强的（Argo 主会话 + Astra / high）。

## 协同

触发词：「直接调度」「你来调度」「你来安排谁做」「总舵主」。

进入条件：方案已有，带能判定的验收标准，且有不止一件能独立验收的活。方案可以来自 Plan 模式产出、别处的方案文档、旧的 plan，或探讨、复盘的结论。

步骤：

1. 第 0 节选模型。
2. 读方案，拆成能独立验收的活，每件判四点（见 `division-of-labor.md` 第 5 节）。
3. 第 8 节出推荐表：每件活写推荐执行方（型号·强度）、推荐理由、备选、大概多久，写进 plan §10。
4. 把推荐表按纪要模板「推荐谁做什么」那一段的写法交给主席，问一句：按推荐来，还是改哪几条？
5. 主席定了才派。答复记账本「主席指令」，结果填 §10「主席定」列。
6. 第 9 节执行与验收，证据写进 §11。
7. 交完工报告（配方见 `minutes-template.md` 末尾）。

最少文件集：brief.md、plan.md（§2 验收、§10 分工表、§11 执行记录）、ledger.md（主席指令、调度记录）、rounds/ 下的任务书和验收记录。

主席开口：开头选模型；看推荐表定分工；执行中撞到要跨方向改派或额度到顶时拍板；最后收完工报告。

模型默认值：按主席在第 0 节选的执行方向；他说「你定」时按 `division-of-labor.md` 第 7 节的表排推荐。
