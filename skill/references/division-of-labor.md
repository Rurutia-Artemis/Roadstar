# 调度：怎么读额度、怎么判活、派给谁、怎么验

主席开场一句话定这次模型怎么用，Argo 按这里的规则把每件活派下去、派完回来审。这里给的是默认判断和初值，跑两三场按调度记录调。

主席开场后改的方向和在拆分表上改的人，压过这里所有默认值；这里的表用来生成推荐和理由。

## 1 各方能做什么

| 参与者 | 结构性优势 | 默认派给它的 |
|---|---|---|
| Argo（Claude Code 主会话） | 主席就在这个会话里，插话零成本；Plan 模式；本仓库全部 skill（vela / apple-hig / 写作三把刀）；Obsidian 共享记忆读写；内置浏览器与 Claude in Chrome；iOS 模拟器；Artifact | 规划与取舍、起草与改稿、写任务书、调度、最终整合与裁定、需要主席频繁拍板的活 |
| Claude 子代理（Haiku / Sonnet / Opus） | 和主会话共用一份 Claude 额度，便宜型号扣得慢；能并行，中间上下文不进主会话；用得上本机全部 skill、记忆、模拟器与浏览器 | 只在 Codex 紧或空、Claude 正常或宽时接实现与取证：Haiku 机械批量与只读取证，Sonnet 规格清楚的实现与只读复核，Opus 难活、根因诊断、画样张；Fable 不当子代理。主席 2026-10-10 定 |
| Dex（Codex CLI） | 另一家模型，盲区与 Argo 不重合；独立沙箱与审批策略；`--output-schema` 结构化输出；能换型号跑不同分量的活；主席的 Codex 侧有生图能力与 C2C 桥（连 Pro） | 审稿和难实现用 `gpt-6-astra`，常规实现、机械批量、只读取证和复核用 `gpt-6.1-sol`（强度按活 low / medium / high）；Luna 不派活；生图类任务。主席 2026-10-09 定：Dex 不拆活、不分配、不做决定，只在讨论环节提意见、执行环节干活和复核 |
| Pro（网页 GPT Pro） | 主席实测推理水平与 Claude 相当，GPT 侧最强；慢，走网页，不直接读仓库 | 大方案起草、定稿终审；Codex 空时的跨家审稿兜底 |
| 主席 | 目标、取舍、预算、验收 | 开场定模型用法、争议裁决、开工与定稿的最后一句话 |

型号细节见 `models.md`。

主席 2026-10-05 定：实现一律交 Codex，Claude 主会话只做调度、任务书和验收，不再派 Claude 子代理，避免子代理消耗 Claude 额度。主席 2026-10-10 改：实现默认仍交 Codex；Codex 紧或空而 Claude 正常或宽时，走 Claude 子代理梯子 Haiku → Sonnet → Opus，Fable 不当子代理；Claude 周窗紧或空时梯子关闭。需要浏览器或模拟器核验的活，由 Claude 主会话自己做，或交具备环境的 Codex 或 Claude 子代理。

## 2 额度怎么读

一条命令：`scripts/quota-status.py`。它只读、不花额度，两边各出一行读数加档位；`--json` 给机器读。

- Claude 看三项：5 小时窗、周窗、Fable 单列，三项各算一档，取最差的。Fable 最多占周额度一半，主会话是 Fable 时这一项先到顶。
- Codex 看周窗（有 5 小时窗也一起算，取最差）。重置卡数脚本能读到，写在 Codex 那一行。
- 命令行不在或超时，脚本退回最近一份读数并标多久前；读不到的项照实写「读不到」。

## 3 档位与阈值

每一项用「窗口过了几成、用了几成」比。按下面顺序判，命中即停：

| 档位 | 条件 |
|---|---|
| 空 | 用了 95% 以上，且 6 小时内不重置 |
| 紧 | 用了 85% 以上，或用量比时间进度快 15 个点 |
| 宽 | 用量比时间进度慢 15 个点且不到 70%；或 12 小时内重置且不到 80% |
| 正常 | 其余 |

连着两次读数都越线才换档，免得反复改派（脚本的 `--prev` 读上一次的 `--json` 输出做这件事）。两边各留一成底，给 Mia（常驻 Codex 的 Luna）和主席别的会话：派活按 90% 当顶。

## 4 主席的话和读数谁算

主席一句话定方向，读数只决定能不能派、什么时候停。重置卡的意思是「到顶时停下等主席刷卡」，不等于现在就宽。主席的硬话和读数撞上（例如主席指定 Astra，Codex 周窗已经紧），照硬话排，纪要里报一句冲突，让主席知道代价。

## 5 每件活判四点

- 难度。难：要取舍、跨模块不变量、并发、迁移、权限、钱、时区与夏令时、幂等与重发、定时跨日、根因不明、主席说过「重要、不放心」。中：接口和验收写清楚的实现。易：机械批量、格式、照抄模式。
- 验收条件。命令行能验，还是要浏览器、模拟器、本地服务、真机。
- 执行环境。开发过程本身要起浏览器、本地服务、模拟器、SwiftUI 构建或联网装依赖的，先核对 Codex 的实际环境，写进任务书；缺少环境时由 Claude 主会话或主席跑所需命令、回传证据，代码仍交 Codex 改。只有验收那一步要这些的，Codex 写、Claude 主会话核验，或交具备环境的独立 Codex 会话。要真动 /Applications、LaunchAgent、Obsidian、生产的那一步，只能 Argo 或主席做；脚本交 Codex 写，沙箱里只碰工作区内的临时路径。
- 上下文。任务书写得全就能派；离不开主会话的，先把上下文写进任务书再派。

## 6 优先顺序

多条同时命中按这个顺序取第一条：主席硬话 > 执行环境 > 验收条件 > 难度 > 额度方向。

## 8 验收分级与配对

- 易：执行方自测，Argo 读 diff。
- 中、难：Codex 做的由 Claude 主会话自己跑验收命令核对，或另开一个 Codex 只读会话复核。Codex 复核不续接执行会话：Astra 写的配 6.1 Sol / high，6.1 Sol 写的配 Astra / high；主会话记明属于同家独立会话复核并裁定。优先跨家：Claude 梯子写的配 Codex 6.1 Sol / high 只读复核，Codex 写的可配 Sonnet 子代理只读复核。
- 钱、权限、迁移类（含写工作区外、动生产）：不接受执行会话自己验收，也不接受仅同家复核。Codex 实现配 Claude 主会话，主会话自己跑钱、权限、迁移与回滚的验收命令，逐条核对实际状态；Claude 主会话执行的工作区外操作配独立 Codex 只读会话。另一家空了就请网页 Pro 审证据，或等它重置、问主席刷卡，或主席亲自验；纪要里说清选了哪条，代码审查不能代替实际状态核验。
- Codex 空又需要独立复核：Claude 主会话自己跑命令，或开 Sonnet 子代理只读复核并在账本记明同家；需要 GPT 侧第二意见时先请网页 Pro，或挂起等 Codex 重置。
- Argo 自己动手的整合小修（合并冲突、命名撞车、几十行以内）超过 30 行，派 6.1 Sol / high 只读复核一次；30 行以内读 diff 自查并在调度记录写一行。
- 有界面的活：除了跑命令，Argo 按 vela 的 `references/ui-acceptance.md` 亲自验——逐张逐字看截图、在模拟器里走主席的核心任务、对照样张和口味样本；执行方自测全过不等于界面验收通过。
- 改完再验只在改到同一处逻辑时做。

执行方与审查人的速查表在 SKILL.md 第 8 节；审查人和执行方型号不同。

证据写进 plan §11 和 `rounds/check-T<n>.md`：具体命令与输出摘要，不写「通过」两个字了事。

## 9 怎么派

0. 拆分表先给主席看：探讨和复盘随纪要交、主席说开工就派；协同报一次就派，主席改哪条停那条重派。

派活前复读一次额度，每件活先按 `task-brief-template.md` 写好任务书。

Codex：

```bash
scripts/dex-exec.sh <plan-dir> T3 --model gpt-6.1-sol --effort medium --brief <任务书路径> \
  --max-minutes 120 [--root <项目根>] [--write] [--detach] [--resume <session id>] [--status] [--force]
```

- 默认 `-s read-only`；要改文件加 `--write`（换成 `-s workspace-write`）。`--root` 不给时取 plan-dir 所在的 git 根。
- `--max-minutes` 是止损，写拆分表里的上限（常规 120、难活 240、窄回归 60）：到点脚本停掉 codex，退出码 124，meta 记 `timed_out=1`，`--status` 会提示「到时间上限被停止」。停掉的线不自动重派，Argo 先看进度文件和日志诊断（第 15 节），再决定收下、换环境判还是缩窄重派。
- 常规实现、机械批量、只读取证用 `gpt-6.1-sol`（low / medium / high 按活选），难活用 `gpt-6-astra`（high / xhigh）。脚本显式传 `-s`、`-m`、`-c model_reasoning_effort=`、`--disable fast_mode`；返工续接按现有 CLI 写法用 `-c` 覆盖型号和沙箱。
- 长任务加 `--detach`，脚本立即返回；`--status` 查运行中还是已结束、退出码和 meta。
- 返工加 `--resume <session id>` 接着原会话，session id 在 `rounds/exec-T<n>.meta`。
- Codex 档位是「空」时脚本拒派，`--force` 放行，用前要有主席的话。
- 产物都在 `rounds/`：任务书副本 `exec-T<n>-request.md`（再派一次是 `-r2`）、回复 `exec-T<n>.md`、`exec-T<n>-stdout.log`、`exec-T<n>.meta`。

独立 Codex 复核：另写只读验收请求，给任务书、执行回复、diff 和验收标准，不传执行 session id。复核者只读、自己跑命令，报告由主会话保存到 `rounds/check-T<n>.md`：

```bash
codex exec --skip-git-repo-check -C <项目根> -s read-only -m gpt-6.1-sol \
  -c model_reasoning_effort=high --disable fast_mode \
  -o <plan-dir>/rounds/check-T3.md - < <只读验收请求路径>
```

上例配 Astra 的实现；6.1 Sol 的实现改用 `-m gpt-6-astra`，强度仍显式传 high。`-o` 由 CLI 保存报告，不给复核会话工作区写权限。

Claude 梯子（只在走 Claude 梯子时）：用 Agent 工具派，`model` 按层选 haiku / sonnet / opus，不用 fable；任务书原文当提示，写明「结果写回 <plan-dir>/rounds/exec-T<n>.md（绝对路径）」和时间上限；主会话收到回复后手写 `rounds/exec-T<n>.meta`（型号、起止时间、上限、派前后 Claude 读数）。到上限主会话用 TaskStop 停，停掉的不自动重派，和 Codex 线一样先诊断。Claude 周窗读到紧或空时不派，退回 Codex 梯子或第 11 节。

主席在 Codex 应用里做的活（生图、要走 Pro、要交互）：主席对 Codex 说「按 <任务书路径> 做 T3」，结果写回 `rounds/exec-T3.md`；主席说「T3 做完了」，Argo 读文件验收。

并行与合并：

1. 每件并行任务各开一个 worktree（Codex 用手动 `git worktree add` 再 `--root` 指过去）。
2. 大搬运类（批量改名、移目录）先单独落地，再开并行。
3. 全部回来后 Argo 按依赖顺序合并，合完跑一次全量验收。

## 10 改派与失败上限

**止损先于重试**：每条线有时间上限和检查点，指标不收敛就停，见第 15 节；停下的线不自动改派，先由 Argo 诊断。

一件活执行两次、改派一次，第三次 Argo 接手调查和裁定或交主席，实现仍交 Codex，每次都记进调度记录的失败次数。改派时任务书末尾带上已有 diff、验收输出和 worktree 路径，下一个执行者不重读仓库。改派不越过主席定的型号和强度；换梯子（Codex 换 Claude，或反过来）算换方向，先问主席一句。

## 11 两边都紧或都空的梯子

按顺序走，走到能继续为止：降一档强度 → 并行改串行 → 不急的挂到重置后 → 问主席刷不刷重置卡 → 停。每一步记进调度记录，停了就在纪要里写重置时刻。

问主席时的说法：「Codex 用到 90% 了，剩两件实现。按你定的方向我先等它周日 10 点重置；要是想现在做，刷一张重置卡告诉我。」

## 12 常驻指令放哪

本场的记账本「主席指令」区；跨场的（例如「这个项目难活一律 Astra」）记项目 CLAUDE.md。优先级：账本 > 项目 CLAUDE.md > 额度。

## 13 成本怎么记

按每批派活前后的读数差记进账本调度记录，完工报告写一行。stdout 里的 tokens used 不当成本：它不含缓存读取，会低估两到八倍。任务自己会调模型的（例如评测脚本）单列一行预算。

## 14 主会话是什么模型

- Fable：只做判断、任务书、裁定，更要省，因为 Fable 最多占周额度一半。
- Opus：账本记实际型号；难判断加一次 Astra / xhigh 的第二意见。
- Sonnet：建议主席先切模型再开。
- 不管主会话是什么型号，Claude 梯子的子代理都和它共用周窗；派前看 Claude 读数，Fable 那一列不受子代理影响，但周窗会。

## 15 拆分、并行与真验收（2026-10-07/08 Mia 移动版实战教训）

两天里每个坑都真出过事，左边是现象，右边是以后的做法。派活前按这张表过一遍。

| 出过的问题 | 以后怎么做 |
|---|---|
| 一份任务书塞七八件事（网络 + 主机 + UI + 合并冲突 + 全量排查），一跑四到八小时，交回来一半做了一半写「待处理」 | **一份任务书一个目标**：独立的事超过三件、或跨两个以上模块负责区，就拆成多份并行。单件目标是两小时内能做完、能验收 |
| 终端性能没写「多顺才算完」，Codex 修了能修的就交，主席拿到「解决一半」 | **完成线必须能失败**：写成数字或可观测的条件（例：持续输出主线程 < 15%、0 次 >250ms 卡顿、50ms 内有发送反馈），附测法；「顺滑 / 好看 / 稳定」这类词不许直接进任务书，要么翻成指标，要么附样张逐元素对照。达不到就写没达到、差多少，不许交成「完成」，Argo 也不许发版 |
| 几条线同时改同一个登记文件 / 路由 / 大 Store，合并时冲突、同名类型撞车，还停在一半 | **按文件归属切线**：共享中枢（登记表、路由、壳、几千行的大文件）只归一条线，其它线只经扩展点追加；实在要动的串行。每合一条就整包编译一次，再合下一条 |
| 沙箱里起不了模拟器、监听不了端口，执行方只能写「待沙箱外验证」，第一版装到手机全屏点不动 | **要点界面、起模拟器、开端口的验收不能留在沙箱里**：要么 Argo 自己跑，要么让 Codex 用 `-s danger-full-access` 跑，并在任务书里写死边界块（只改本 worktree、临时端口、自建专用模拟器、不碰生产与用户数据、`HISTFILE=/dev/null`、不提交）。UI 验收要用 XCUITest 这类真点的自动化，截图逐张看 |
| 三台模拟器同时跑，主机负载两百多，同机的微信接入看护超时把整条链路停了 | **同时要模拟器的线最多两条**；每条自建、自删自己的设备，收尾不许 `simctl shutdown all`；重活跑完先查同机生产服务还活着（端口在听、状态不是 failed），挂了立刻告诉主席 |
| 测试 shell 往 `~/.bash_history` 写了一百多行；每条线一个 worktree 各带 10–20 GB 缓存，两天攒到 256 GB | 测试 shell 一律禁历史写入；**合并后立刻把该线 worktree 挪进废纸篓**（不永久删，提醒主席清空），旧安装包、旧测试产物同样处理 |

## 16 项目常驻边界文件 `docs/roadstar/_common.md`

每个项目一份，跨场复用，任务书模板里「项目常驻边界」槽位引用它。内容只放每条线都要遵守、又和具体任务无关的东西：

- 不能碰的东西：生产服务地址和端口、用户数据目录、钥匙串、`/Applications` 下的安装件、常驻网关；要真动这些由 Argo 或主席做。
- 测试资源：临时端口段、模拟器命名前缀与同时上限、构建缓存目录、`HISTFILE=/dev/null`。
- 项目的验收命令：全量测试、e2e、lint 各一条，期望输出或退出码。
- 收尾：自建的模拟器自己删、临时服务自己关、不提交不推送、worktree 由 Argo 合并后挪废纸篓。
- full-access 边界块（第 15 节那段）原文。

没有这个文件的项目，第一场由 Argo 起草（二十行以内），随 brief 一起提交；之后每踩一个新坑当天追加一行，不等主席提醒。
