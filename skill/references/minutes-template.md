# 纪要模板（写给不看代码的主席）

停机后主席只看这一份。他不认识账本代号，不读命令，只想知道三件事：结果是什么、谁做什么、他要答什么。按下面顺序写，每段只写该段的内容，不写过程。

```markdown
**结果**：方案定了，可以开工。／还差一件事：…。／卡住了，要你选（见下）。

**我们商量出来的方案**
三到五句大白话。先说现在的问题是什么，再说打算做成什么样，最后说怎么算做完。不写文件名、不写字段、不写命令。

**这版要做的功能**（做了功能地图时写）
必做 N 项：功能一（用户得到什么）、功能二（…）……；下版再说 M 项；不做 K 项，理由见 feature-map.md。两家讨论中多想出来的、你原来没提的功能，单独点出两三个。

**讨论中改了什么**
- 原来打算…，Codex 指出…（一句说清后果），改成…。
- 原来打算…，Codex 用实际记录证明…，改成…。
- 原来…，改成…。
另外还修了 N 处细节（一句概括是哪类）。

**你要做的**
1. 开不开工；排活表改不改哪条？（例：第 3 件换 Codex 的 Astra）
2. 一句话问题。选项：A / B。我的建议：A，因为…。（只问做不做、花多少、要什么舍什么。）
除了第 1 条没有别的要问，就只留第 1 条。

**排活表**
（`scripts/schedule.py` 的输出原样贴，形状如下；例子见 screens.md）
拆分表（<策略>；<额度方向一句>；预估按<来源>，置信度<高/中/低>）
 #  事  给谁 · 强度  为什么  预估  预计完成  审查人  依赖
 1  人话任务名  我 / Codex 的 Astra · 高 / Codex 的 6.1 Sol · 中 / Sonnet / 网页 Pro / Grace / 你  一句话：难在哪或省在哪  45 分  17:20  我复跑 / Codex 的 6.1 Sol 只读 / 你点头  2
 ……（超过 8 件写「另 N 件同类，同第 k 件的配置，预计 HH:MM 前陆续完成」）
 线上工时合计 X（含复核）；我这边任务书、验收、合并共 Y；并行 N 条 Codex 线；关键路径 1 → 3 → 6
 预计全部完工 HH:MM JST（从你说开工起算，等你点头的时间不算）
 额度：Codex 本周预计 A% → 约 B%；Claude …
 开工就按表派，改哪条说一声。

细节在：docs/roadstar/<日期>-<slug>/
```

写法要求：

- 「给谁」只用这几种写法：「我」「Codex 的 Astra」「Codex 的 6.1 Sol」「Haiku」「Sonnet」「Opus」「网页 Pro」「Grace」「你」，后面用「· 低 / 中 / 高 / 很高」写强度。Argo / Dex 这些标签只在账本和文件里出现。
- 「为什么」每件一句，说这件活难在哪、为什么配这个人，或者省在哪；表前一句写主席开场选的方向。
- 议题编号、阻塞 / 建议这类严重度标签、字段名、命令、工具名、脚本名，一个都不进纪要。专有名词要用就在括号里解释一次。
- 「讨论中改了什么」只挑改变结果的，最多三条；每条都要说清「不改会怎样」。
- 「你要做的」第 1 条固定问分工；其余每件先选项后建议，能一个字答。
- 「预估」和「预计完成」由排期脚本算，表头写明来源和置信度；是估计，纪要里说是估计。Grace 的活写「交回后并入」，不计入完工时刻。
- 整份一屏内。写完自检：一个没看过代码的人能不能只靠它知道结果、谁做什么、要答什么；不能就重写。
- 逐轮模式的每轮汇报同一配方，「讨论中改了什么」只写本轮。

## 例子（本仓库 audit-usage 那场）

**结果**：方案定了，可以开工。

**我们商量出来的方案**
现在盘点哪些 skill 该退役时，脚本只数「在 Claude 里被明确启动了几次」，数不到 Codex 那边的使用，也数不到通过工具接口和参考文件的使用，所以会把还在用的 skill 当成没人用。这次改成数四种使用：Claude 里启动、工具接口调用、Codex 里读过、参考文件被读过；再加一列「数得全不全」，数不全的 skill 一律不进退役名单。做完的标准：老功能一个字不变；整机扫一遍 60 秒内（试跑 30 秒）；一套自动测试证明四种数法都数对，不多算也不漏算。

**讨论中改了什么**
- 原来打算按文字找「启动了某 skill」这句话，Codex 指出说明文档里也有这句，会多算，改成只认真正的启动记录。
- 原来用一条简单规则判断 Codex 有没有读过某个 skill，Codex 用实际记录证明它既会多算（把搜索关键词当成文件）也会漏算（带管道的命令），改成按命令逐段解析，看不懂的命令标「没数到」而不是算零。
- 原来扫描超时就只看近 90 天，Codex 指出这是偷偷缩目标，删掉了，改成先实测，30 秒够用。

## 完工报告（开工后的第三次开口）

```markdown
**做完了**，可以用了。／**做了一半**，卡在…。

做了什么：一两句人话，对应纪要里的方案。

怎么验的：老功能对照改前输出，一字不差；整机跑一遍 X 秒；N 条自动测试全部通过；我跑验收命令核对 Codex 的实现，或另开 Codex 只读会话复核，挑出的问题已修。（数字写实际值，没做的项写「没做」。）

预估对账：N 件预估 X，实际 Y，偏差 ±Z%；最准的是…（预估 a，实际 b），最偏的是…（预估 c，实际 d，原因一句）。这一格样本还不到 5 条，默认值先不动，偏差已记进本机校准表。／样本够了，下一场这类活按本机记录估。

额度：Codex 本周 X% → Y%（排活表预计 Z%）；Claude 5 小时窗 X% → Y%，本周 X% → Y%。

清理：删了 N 个已合并的 worktree，释放 X GB；M 个有未提交改动没动（路径在报告里）。／只列了清单没删，点头我就删。

没做完的：无。／逐条列，每条一句说卡在哪。

你要做的：没有。／一句话 + 选项。

记录在：docs/roadstar/<日期>-<slug>/，共享记忆已写，已回传 N 条。
```

要求同纪要：自称「我」，对方写「Codex」，不出现文件名以外的技术名词；验证结果只写跑过的，测试挂了就写挂了几个；预估对账、额度、清理三段的数字来自 `.meta`、探针和 `cleanup.py` 的输出，不手填。
